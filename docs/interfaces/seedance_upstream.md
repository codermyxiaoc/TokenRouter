# Seedance / 火山方舟原生视频任务

本文覆盖旧 OpenAI API Key 账号的 Ark 异步视频任务准入、原生协议、任务归属和完成后计费。这条 Seedance 能力继续复用 OpenAI 账号与媒体任务基础设施，不改变 Grok 视频的按秒计费规则。新增 `platform=video` 的 Ark 端点由[独立 Video 上游](video_upstream.md)拥有，两条链路按创建分组和已保存的任务归属分流。

<a id="seedance_task_lifecycle"></a>
## 账号与任务生命周期

账号必须属于 OpenAI、类型为 API Key、配置自定义 Base URL，并显式选择 `openai_workload_capabilities` 中的 `seedance`。管理端创建、编辑及批量修改均提供该选项；未配置能力的旧账号继续默认文本与 Embeddings，不自动获得视频能力。方舟 Base URL 可设置为 `https://ark.cn-beijing.volces.com/api/v3`，站点根地址会补齐 `/api/v3`，代理地址已有路径前缀会保留。模型 ID 可以是方舟模型名或模型推理接入点 ID，仍受分组、渠道及账号模型规则限制。

内部 Redis 调度精简投影必须同时保留 `base_url` 和显式能力字段，确保缓存候选与完整账号的资格判断一致；地址缺失时不能仅凭能力开关放行。升级前缓存若缺少地址，由现有启动全量重建或账号更新 outbox 重建恢复，无需清空 Redis。启动重建在后台执行，完成前旧缓存可能暂时拒绝视频请求；滚动升级需完成所有节点更新，避免旧进程再次写入缺字段的投影。OAuth、未勾选能力和未配置地址的账号仍不可用于 Seedance。

支持以下等价任务根路径：

- `/api/v3/contents/generations/tasks`
- `/v3/contents/generations/tasks`
- `/v1/contents/generations/tasks`
- `/contents/generations/tasks`

`POST` 根路径创建任务，`GET /:task_id` 查询，`DELETE /:task_id` 删除。创建 JSON 必须包含非空 `model` 和非空 `content` 数组；扩展多模态字段原样转发，不转换为 Responses 或 Chat Completions。模型映射只改写请求侧 `model`，原生响应不进行客户端模型别名还原，不包装成平台业务响应。上游 HTTP 错误保留其状态和正文，并进入现有运维错误采集链路。

创建复用现有鉴权、计费准入、并发槽及媒体生成权限；当前分组的媒体入口沿用“允许图片生成”开关。智能路由可在提交前选择具备模型和视频能力的 OpenAI 分组。创建完整返回明确未受理错误且没有规范任务 ID 时，可交回现有 handler 在原换号预算内尝试同组其它账号；参数、审核、通用网关错误和传输中断不重提，不跨分组重放。已收到规范任务 ID 的错误也先持久保存归属再返回原错误，后续固定原账号查询；`request_id` 仅为追踪号，不冒充 Seedance 任务 ID。

创建前检查任务数据库可访问，上游创建成功后先持久化用户、API Key、分组和上游账号归属及结算快照，再向客户端提交原生响应；保存使用独立的有限时上下文，避免客户端断连立即取消持久写入。数据库前置检查不是跨上游分布式事务；受理后归属或快照最终仍无法写入时，返回 `503`、`TaskStorageUnavailable` 和已创建的原始任务 ID，提示不可重新提交，运维可凭任务 ID 排查，服务端不自动重创或取消付费任务。

内部任务键增加 `seedance:` 前缀以隔离 Grok 同名任务，客户端收到的 ID 仍为上游原值。查询和删除必须匹配创建者与 Key，并固定原账号；不会拿另一个账号尝试相同任务 ID。普通 Key 改绑分组后不自动取得旧分组任务的查询权限；复合/智能 Key 查询可按已保存归属恢复原分组，并继续校验可访问范围。

查询、删除不是新的消费请求，因此可在余额或 Key 额度用尽后继续读取、取消已有任务；用户/Key 禁用、IP 限制、租户权限和任务归属检查仍然有效。仅精确匹配的任务详情路径享受此边界，集合查询、未知路径及嵌套路径不能借此绕过消费准入。

成功删除在返回原生响应前持久保存 `upstream_deleted_at`，旧缓存任务按已验证的原归属原子补录；缓存资金快照缺失不阻止记录删除事实。写入失败保留任务 ID 并明确上游已删除，只重试本地保存，不重复发送 DELETE。删除不撤销执行租约、不清除完成证据、冻结报价或付款回执，已在途查询得到的真实完成结果仍可保存并结算。空删除响应不能证明没有生成费用；缺少完整完成用量的已删除任务停止主动上游查询并保留账务待核对，不能因之后的 404 自动认定免费。

<a id="seedance_billing"></a>
## 完成后计费与恢复边界

任务创建时保存计费模式、选定订阅、分组配置、原始客户端模型与渠道映射快照，剔除预加载账号及用户资料。后台结算时使用创建快照恢复扣费上下文；改动 Key 的结算方式或另购套餐不会把旧任务转移到新套餐。自动模式通过仅服务端设置的 `SubscriptionScopeID` 限制原套餐参与分摊，余额继续按现有规则补足；创建时无套餐则固定走余额。该约束不改变普通请求候选订阅和幂等指纹。

快照固定的是结算选择，不是额度预占。完成时原套餐到期、失效或不再覆盖分组，自动模式可由余额承担；指定订阅模式仍按现有规则报告结算失败，不擅自改扣另一套餐。指定订阅仍有效但额度不足的已放行任务，保留原有溢出余额欠费策略。后台恢复持续重试结算；缺价、缺快照等无法安全自动处理的任务保留待核对，不能因为客户端已拿到视频就认定扣费成功。

只有查询返回 `status=succeeded` 且 `usage.completion_tokens` 为正数才进入结算，复用现有输出 token 价格、分组倍率、余额/订阅扣费和使用记录链路。管理员必须为实际结算模型配置输出 token 单价。缺少或为零的 usage、未完成和失败任务均不会按时长推算费用；此路径不使用 Grok 视频按秒价。

结算使用数据库租约与任务级稳定计费 ID。后台先保存终态用量、再持久化首次报价和安全扣费命令，然后执行扣款；实际资金分配回执与扣费在同一事务保存，使用记录失败后只重放原回执。限定原订阅的报价使用创建快照保留的套餐分组倍率，并冻结最终资金倍率；后续修改套餐倍率不能改变该报价，高峰因子只叠加一次，媒体独立倍率仍优先。套餐当前资格、剩余额度和余额补足规则继续在结算事务中校验，普通请求的多订阅分摊不受此冻结规则影响。客户端查询不再领取一次性 Redis 计费锁，也不依赖请求结束后的临时队列执行扣款。

任务归属和待结算快照保存在 PostgreSQL `legacy_video_tasks`，旧 Redis 24 小时缓存只作为兼容恢复来源。后台每五秒有界领取任务，原账号查询与安全重试不依赖客户端轮询；升级时仅扫描最近七天已有任务，历史缺少快照不得猜测补费。进程中断后数据库租约过期可由新实例继续，重复执行不会产生第二笔费用。

任务列表以 `seedance_video` 来源保存创建、查询和删除时的安全状态投影，展示原始上游任务 ID，不展示内部 `seedance:` 前缀。列表读取不调用上游；状态由创建、合法查询和独立后台恢复推进。`succeeded` 可以标记生成完成，但缺少 usage 或结算失败时不能据此认定已扣费；查询 HTTP 错误不等同于任务失败。投影不保存原始请求、响应、素材地址或凭据，后台投影写入失败会重试，不重新生成或重复扣费。成功查询中的完成产物地址和白名单媒体属性可另存 Redis 短期预览快照；面板预览只读取该快照，通过短期本站票据播放，不重新查询任务或触发结算，详见[任务结果预览](../domains/media_tasks.md#media_task_preview)。

### 服务端持久恢复

方舟原生任务与 Grok 共享 `legacy_video_tasks` 和 `LegacyVideoRuntime`，在返回创建成功前持久保存归属和原资金快照，服务器自行轮询原账号并补写状态、真实 Token 扣费与使用记录。重复执行依赖数据库租约、任务级幂等键及同事务扣款回执，不能以 Redis 一次性领取代替持久结算。创建/查询完整响应预算分别不超过 120/30 秒，并保留更短的调用方截止时间；创建不跟随重定向。完整恢复与历史快照缺失的处理见 [Grok 任务归属与结算](grok_upstream.md#grok_video_ownership)。
