# 智能路由 API Key

本文覆盖智能路由 Key 的候选配置、模型目录匹配、跨平台选组、失败换组、冷却和无模型入口。分组内部的账号排序、上游协议转换及结算由现有网关流程负责。

<a id="configuration"></a>
## 配置与存储

创建密钥时提交 `smart_routing: true` 和 `smart_routing_group_ids`，例如：

```json
{
  "name": "开发路由",
  "smart_routing": true,
  "smart_routing_group_ids": [12, 7, 25],
  "smart_routing_cooldown_seconds": 60
}
```

列表包含 1 至 10 个互不重复、当前用户有权使用的有效分组，数组顺序就是候选顺序，允许跨平台。智能路由、普通 `group_id` 和 `is_composite` 前缀模式互斥。更新省略配置字段时保留原值；提交候选列表时完整替换。响应中的 `smart_routing_groups` 提供按候选顺序排列的分组摘要。切回普通 Key 需要关闭智能路由并提供目标 `group_id`。指定订阅模式要求全部候选属于该套餐覆盖的分组。

`api_keys.smart_routing` 保存模式，候选顺序复用 `api_key_composite_groups` 关联表；内部前缀只用于保持该表的唯一约束，客户端请求与模型列表不携带它。认证缓存保存候选分组及各组用户 RPM 覆盖，选组只生成请求级 Key/User 视图，不改写数据库绑定或共享缓存。迁移 `269_api_key_smart_routing.sql` 为已有 Key 默认关闭该功能。

`smart_routing_cooldown_seconds` 是整数，默认 60 秒，允许 0–3600。0 只关闭跨请求冷却，当前请求仍会按规则换组。迁移 `271_api_key_smart_routing_cooldown.sql` 增加同名列和范围约束，已有记录默认 60；普通与复合前缀 Key 不启用这项行为。更新省略该字段保留原值，单独更新冷却不重写候选关联或用量。认证快照版本为 v39，旧快照失效后从数据库重建。

迁移 271 保持首次应用时的原文；后续约束范围修正和冷却字段的鉴权缓存 outbox 扩展由 `272_api_key_smart_routing_cooldown_outbox.sql` 执行，不覆盖已有冷却值或修改历史迁移记录。

创建和编辑页面使用同一候选编辑器，支持添加、删除、上移、下移，展示分组平台和倍率；切换指定订阅后裁剪套餐外候选。智能路由开启时展示冷却秒数输入框。列表折叠显示首组与剩余候选数量，使用密钥弹窗展示候选和失败边界。

<a id="request_selection"></a>
## 请求选组

智能路由位于 Key 身份、用户和 IP 校验之后，协议 handler 分派、消费准入和真实账号调度之前：

1. 从 JSON、multipart 或 Gemini 模型 URL 读取非空模型。只计算一次 Key 模型重定向目标用于匹配，原始请求交给统一重定向流程改写，避免递归映射及响应别名丢失。
2. 按候选顺序读取分组，排除停用、缺失、已撤销用户授权或不匹配强制平台的分组。
3. 按当前分组的渠道映射、账号映射和模型限制检查账号模型目录。目录是有限的具体型号集合，包含明确配置和现有平台目录基线；通配符、任意模型透传或仅有价卡不能证明未知型号存在。错误策略产生的 `error` 状态和暂停调度不抹去已配置模型，显式 `disabled` 账号仍排除；只有 active 且可调度的账号能实际接收请求。
4. 没有目标模型的分组直接跳过。对纳入失败观测的文本请求，跳过本请求已尝试和当前 Key 下正在冷却的组；依赖远端续接句柄或不透明压缩历史的请求遇到冷却时直接返回 503，不能借此转投其它组。含有模型的分组继续检查请求端点能力、账号状态、限流、配额、OAuth/privacy 等硬资格和当前并发计数；当前没有可调度账号时继续下一组。
5. 首个合格分组成为本轮尝试的分组，后续权限、协议门禁、指定订阅范围、额度、倍率及用量归属都使用它。基础设施读取失败直接返回错误，不能当成无账号静默换组。

选组检查不获取账号并发槽、不绑定会话、不请求上游。真实 handler 继续执行账号选择、并发竞争和准入复核，因此检查后的状态变化仍可能导致该组返回容量错误。账号重试先在已选组内完成，最终上游 429/5xx 按下节规则处理。协议策略拒绝、余额不足、Key 限额和指定订阅失败不触发下一候选。智能请求继续禁用传统默认分组、Claude Code-only 分组回退和 invalid-request 分组回退，避免逃出候选顺序或发送到目录不匹配的组。

该请求范围在 `simple` 模式同样有效：即使调度快照使用平台级缓存桶，返回候选和实际账号归属校验也必须收窄到已选分组，不能沿用普通简易模式的全平台账号池。

<a id="group_failover"></a>
## 上游失败换组与冷却

认证协调器保留原始请求体，在组内重试结束后检查最终响应和运维上游状态。实际上游 429 或 500–599 且尚无客户端业务输出、未安排用量结算、请求未取消时，暂存错误并按候选顺序继续。每个组在本请求中最多尝试一次，最多 10 组。每轮重新进行 Key、用户、IP、额度、订阅与路由协议门禁检查，并从原始模型执行一跳映射。不会重入整条 Gin 路由链，也不会重复执行外层访问日志。

下一组成功只返回成功结果；所有可尝试组都失败时返回最后实际尝试组的错误及对应响应头，不用后续“无剩余候选”的 404/503 覆盖它。后续鉴权或本地策略错误仍直接返回，不能用智能路由绕过权限和消费限制。运维上下文保留各次上游错误事件，最终消费使用成功尝试的分组、账号和倍率。

全局用户 RPM 对同一客户端请求只递增一次，避免换组重复计数；每个候选组的用户/分组 RPM 仍独立检查并计数，重新鉴权得到的更低限额也会复核。普通请求不共享这一状态。

失败组按照当前 Key 配置进入冷却，包括最后一个失败组。冷却按 **API Key ID + Group ID** 存入 Redis，影响该 Key 对整个分组的模型请求，不修改组和账号状态，也不影响其它 Key。跨实例读写有 250 毫秒上限，并以已有较长 TTL 为准；Redis 故障降级为有界的进程内已知冷却并记录日志，未知状态不会伪造成全组冷却。修改为 0 会忽略已有 TTL，改为其它正值不追溯缩短已经开始的冷却。

客户端断开后排水实际收到的上游 429/5xx，仍由 service 明确标记本轮流失败，再由协调器执行有界、脱离请求取消信号的冷却写入。此时不重放当前请求，也不要求错误帧成功写出才开始冷却。单纯客户端取消，以及组内早先账号失败但最终已成功的历史错误，都不作为新的分组失败。

新请求的模型匹配候选全在冷却时返回 503 `SMART_ROUTING_ALL_GROUPS_COOLING`，`Retry-After` 为最早到期冷却的剩余整秒（向上取整）。目录不匹配仍为 404；模型匹配但无可调度账号仍为原有容量 503。TTL 到期后按原候选顺序恢复资格检查，不会自动解除账号原有的持久停用；这不是主动探活，也不能阻止错误被识别之前已经进入该组的并发请求。

失败观测范围为 POST Messages、Responses（含 compact/input_tokens）、Chat Completions、Embeddings 和 Gemini generateContent/streamGenerateContent/countTokens 及其现有别名。普通推理历史中的 `reasoning.encrypted_content` 不关闭换组；协调器完整保存并重放原始历史，不预先删除密文，目标协议仍由原有适配器处理。工具参数 schema 中同名字段也不影响重试资格。客户端 `function/custom/local_shell` 工具声明及已有工具结果本身不代表本轮已执行远端副作用。

是否允许重放与是否冷却分别判断：带 `previous_response_id`、带密文的 `input` 类型 `compaction/compaction_summary`、后台任务、Responses 生图意图及服务端执行工具仍不跨组重放，但实际失败的组会进入冷却。前两类依赖远端状态的请求遇到模型匹配候选冷却时返回 503 `SMART_ROUTING_CONTINUATION_GROUP_COOLING` 和该组的 `Retry-After`，避免因冷却绕过该候选后将不完整历史发往另一组；这不等于实现了远端句柄归属查询。独立的新后台或工具请求可以在开始前跳过冷却组，但已发出的任务失败后不再次执行。独立图片/视频等任务端点仍不纳入本协调器。普通与复合前缀 Key 保持原行为。

后台日志记录失败组、原始上游状态、冷却秒数、重放限制原因及实际切换的目标组，并携带请求 ID；不记录请求正文或密钥。Responses 转 Chat Completions 的 HTTP 503 在原有 handler 中可能映射为客户端 502，换组判定仍使用真实上游 503。

Responses/Messages 转 Chat Completions 时，上游 HTTP 200 不等于生成成功。流内错误、空流、只有角色前导或完成哨兵的空响应，以及缺少正常终态的连接截断，均须经过流错误判定；不能被转换成空的 `response.completed` / `message_stop`。尚无业务输出及上游用量时，可重试错误交回原有组内重试，再由协调器按候选顺序换组并冷却；已经输出内容或观测用量后，保留部分结果、追加失败终态并记录 Ops，不跨组拼接。最终换组成功也保留被恢复的上游异常记录。具体流终态兼容规则见 [OpenAI 上游](../interfaces/openai_upstream.md#chat_stream_failure)。

错误与 SSE 前导最多缓冲 256 KiB，首次业务输出就放行成功流。已经向客户端输出业务内容或达到缓冲上限后禁止重放；已经排队记录部分用量也禁止重放，避免同一请求账单幂等键冲突。会话隔离只允许释放本轮新建且 token 仍属本轮的临时归属，既有会话归属不迁移；清理失败则停止换组。现有会话跨组限制仍然可能拒绝后继候选。

换组无法撤销上游已经做完但未送达的工作，因此仍存在上游重复计算/计费的可能。首个请求仍需等待原有组内重试和上游超时结束；冷却减少后续请求重复访问故障组的等待，不改变这些超时配置。

## 模型与无模型入口

普通模型列表聚合有权限的候选分组，并按候选顺序对原始模型 ID 去重；Key 的精确别名仅在其目标可请求时追加。Gemini 和 Antigravity 专用列表保持相应平台范围，批量图片列表保留该功能的资格过滤。列表不添加复合前缀，仍执行适用的 Key 额度和订阅校验。

用量、已有批量图片作业管理和已有 Grok 视频任务查询只按 Key/资源归属工作，不选择任意默认组。模型消费请求缺少模型、传入空字符串或非字符串模型时在本地拒绝；客户端 token-count 探针同样必须提供目录匹配且端点兼容的模型。

模型字段必须唯一且无歧义：JSON 重复字段及大小写别名、multipart 重复字段和文件形式的 `model` 均被拒绝，避免选组解析器与转发处理器使用不同模型。Responses 明确的生图工具意图在预选组时传入账号能力和图片限流检查。

Live、Realtime、Responses WebSocket 和 sideband 无法在认证时为整个连接确定单一模型，智能路由与复合 Key 一样明确拒绝。其它没有已实现模型解析契约的端点也不回落首组。

## 错误契约

| 状态 | 错误码 | 含义 |
| --- | --- | --- |
| 400 | `SMART_ROUTING_MODEL_REQUIRED` | 缺少非空字符串模型 |
| 400 | `SMART_ROUTING_INVALID_REQUEST` | JSON 请求无效 |
| 400 | `SMART_ROUTING_ENDPOINT_UNSUPPORTED` | 入口无法安全确定模型或不支持智能路由 |
| 404 | `SMART_ROUTING_MODEL_NOT_FOUND` | 候选账号目录不含请求模型 |
| 503 | `SMART_ROUTING_NO_AVAILABLE_ACCOUNTS` | 匹配目录后没有当前可调度账号 |
| 503 | `SMART_ROUTING_ALL_GROUPS_COOLING` | 当前模型的匹配候选全部冷却，附 `Retry-After` |
| 503 | `SMART_ROUTING_CONTINUATION_GROUP_COOLING` | 续接或不透明压缩历史遇到冷却候选，附 `Retry-After`，不跨组发送 |
| 503 | `SMART_ROUTING_UNAVAILABLE` | 检查依赖缺失或读取失败 |

错误使用入口协议的 Anthropic/OpenAI/Google 原生外层结构。请求体超限保持 `413`，不会被误报为模型不存在。模型列表、选组和配置变更需要一并维护测试。
