## 异步图片生命周期

`POST /v1/images/generations/async`、`POST /v1/images/edits/async` 接受与同步 Images 相同的 JSON/multipart 请求，兼容无 `/v1` 别名，不接受流式请求。异步入口提前拒绝缺失、非字符串或全空白 `prompt`，返回 400 且不受理任务；不修改同步接口的参数规则。功能默认关闭，只有 `image_storage` 已开启、所选 S3 或本地目录后端配置有效且初始任务可落入 PostgreSQL 时才接受任务。提交仍要求有效 Key、图片权限和 OpenAI/Grok 分组；正常提交返回 HTTP 202、任务 ID、相对 `poll_url`、`Location` 和 `Retry-After: 3`。客户端必须主动改用这两个端点并轮询，原有同步 SDK 请求不会自动转成任务。

受理前对本任务冻结的存储配置执行小对象写入、读取内容校验和删除探针；进入后台网关执行前再次检查同一快照。成功探针最多缓存 30 秒，并发检查合并；真实图片上传失败会使缓存失效。探测最多 15 秒，清理使用独立的 5 秒预算。存储不可读写、不可清理或超时会在调用模型和资金预占之前拒绝执行，避免已知不可用的桶继续产生付费图片。探针只能验证当时权限和连通性，不能保证生成结束时存储仍可用。

受理前探测失败返回 `503 / image_storage_unavailable`，不创建任务，并附 `Retry-After: 30`；受理后的执行前检查失败则写入同一分类的失败终态。探针验证 S3 API 的目标目录权限与签名生成，不额外访问 `public_base_url`，公开域名的解析、CDN 和访问策略仍需单独配置。探针使用随机对象键且不包含用户图片；清理本身失败时可能残留小对象，可通过桶生命周期规则清理。

提交前在模型改写之前惰性捕获原始请求。后台在同一进程内部重新进入同步 Images 完整路由，保留可信内部请求 ID，并重新执行认证、模型映射、复合 Key/智能路由选组、并发限制、审核与现有结算；不能直接调用单个 Images handler 绕过外层网关策略，也不能把已经映射过的模型再次送入映射。图片沿用现有安全边界，不加入文本请求的智能跨组失败重放；客户端提交连接结束不取消已接受任务。

完成后的图片先转存已冻结配置的 S3 或本地目录后端，`b64_json` 改写为 `data[].url`。PostgreSQL `image_tasks` 保存任务、执行租约和紧凑结果，Redis 是镜像与临时补偿存储；原有 usage 等 JSON 元数据仍保留。两处都不保存请求正文、API Key 或图片 Base64。URL 下载验证公共目标、重定向与实际拨号地址，不携带上游凭据，不使用环境代理，安全下载客户端在进程内仅共享传输连接池，图片与视频各自的客户端超时设置独立；CGNAT、this-network、云元数据主机及每次重定向都拒绝；响应声明和内容嗅探均非图片时在下载阶段拒绝，后续仍执行位图格式白名单；每张图片默认最多 32 MiB，仅接受 PNG/JPEG/WebP/GIF，转存后的结果 JSON 限制为 1 MiB。缺少图片或空 `data` 不能标为完成。提交时固定存储快照，因此处理中修改/关闭图片存储不会将大图片写回任务数据库或 Redis。

图片下载与上传对网络临时错误、HTTP 429/5xx 分别最多调用三次，退避 250/500 毫秒，并共享存储阶段截止时间；底层 S3 SDK 自身的重试也受该截止时间约束。上传重试复用本张已下载字节和稳定对象键，不重跑此前成功图片、不调用模型、不新增扣费。权限、参数、图片内容、安全校验错误不重试。平台不缩放上游图片，响应实际尺寸由上游决定。

转存失败继续使用 `error.type=api_error`，新增固定 `error.code` 区分来源下载、结果过大或编码无效、存储权限、桶不存在、存储超时及一般上传故障。任务列表与持久投影使用相同的安全分类，旧版错误保持兼容；`image_task.offload_failed` 日志仅记录任务 ID、阶段与分类，不能输出原始 SDK 正文、签名链接或凭据。

`GET /v1/images/tasks/:task_id`（及无前缀别名）要求原用户和原 Key，跨用户或跨 Key 与不存在任务统一返回 404。查询不调用生成、不结算，已接受任务在功能关闭后仍可查询；余额不足或额度耗尽不应阻止取回结果，但身份与 Key 有效性检查保留。任务状态为 `processing`、`completed`、`failed`，失败时在 HTTP 200 的任务对象中返回生成阶段的 `http_status` 与 `error`，不是再次生成。

客户端只对 HTTP 200、`status=processing` 且尚未达到最近响应中 `expires_at` 的任务继续轮询，遵循 `Retry-After`（当前为 3 秒）。`completed` 保存结果后停止，`failed` 读取失败原因后停止，两者均移出待查询队列；任务失败不能因查询 HTTP 200 而继续等待。不存在、过期或归属不匹配的 404 使用相同的 `error.type` 与 `error.code=IMAGE_TASK_NOT_FOUND`，收到后停止该 ID 的查询并核对原 Key，不把它当作可无限重试的临时错误。达到 Unix 秒时间戳 `expires_at` 也停止，不因后台仍有任务历史或桶内仍有图片而延长轮询。网络及临时存储故障仅允许对原查询有界退避，不重新提交生成；停止轮询不触发退款、释放或重新扣费。

图片沿用网关的价格与用量规则。异步任务依次执行**转存、结算、发布完成结果**：固定图片价在调用上游前预占资金，生成成功只登记捕获动作（`AsyncImageDeferredCapture`），预占在请求收尾标记为待核对并保持冻结；图片转存成功后，先把转存后的紧凑结果与扣费请求 ID（与网关结算相同的 `client:<请求 ID>`）作为待交付结果写入仍为 `processing` 的任务记录（`pending_result`、`billing_request_id`，查询接口不返回），并读回确认；写入失败或任务已不在执行中时**不扣费**，任务记为 `failed / 503`、`code=image_billing_unavailable` 并释放预占。登记成功后、任务标记完成**之前**执行捕获（按 0/2/10/30/60 秒重试，独立 5 分钟预算）。捕获成功才写入 `completed`。捕获报错时先按扣费请求 ID 与任务所属 Key 只读核对去重账本（含归档）：已提交（回执丢失）照常交付；确认未提交时任务记为 `failed / 503`、`code=image_billing_unavailable`，提示未扣费，不返回结果链接，并释放预占；账本无法查询时同样失败，但提示无法确认扣费而不断言未扣费。转存失败、结果非法、执行异常或 panic 同样释放。捕获和释放各自只在成功后才算完成，一次数据库故障不会消耗结算机会；两者互斥，已扣费的任务不会再被释放，已释放的不会再扣费。

上述异步延迟结算路径**不写**后台恢复证据（`SkipImageSettlementEvidence`）：若进程在捕获资金前退出，任务由维护器按租约与硬期限判为中断失败，预占按[失败任务账务处理](#media_task_reconciliation)的期限释放，不会被后台恢复补扣。渠道 Token 图片等无预占的后结算同样延迟到转存成功后记账；同步 Images 仍沿用自己的生成后结算路径。

捕获成功后的完成结果落库由 `persistDeliveredResult` 继续重试，等待间隔为 0/1/5/15/30/60/120/120/120/120 秒，每轮保存使用独立 15 秒预算并保留底层写入重试；只重试同一结果，不重新生成或扣费。这是当前执行者内存中的有界重试，不是持久消息或重启后可恢复的结果队列。全部保存失败时记录 `image_task.delivered_result_persist_failed_after_capture` 和任务 ID，不记录结果 JSON 或签名链接，也不直接把已扣费任务改写为失败。执行者停止续租后，维护器在行锁内处理租约过期的任务：记录带待交付结果时，在同一事务内只读核对该扣费请求 ID 是否已进入去重账本（含归档），已扣费则把待交付结果写为 `completed`（沿用原 HTTP 状态），未扣费仍按 `execution_interrupted` 失败，由预占的既有期限规则处理；两种情况都清除待交付副本。

因此进程在捕获资金后、结果持久化前退出，或数据库持续不可写，恢复后都由维护器自动补交结果，不需要人工补交。仍需人工核对的边界：图片对象在补交前已按保存期删除（默认 24 小时）；账本记录的 API Key 与任务所属 Key 不一致或扣费请求 ID 缺失时，维护器无法确认扣费而按中断处理。已捕获费用不能用预占释放接口撤销，此类情况按任务 ID、原账本和桶内稳定对象键核对处理。旧的存储失败记录没有保留原始图片或上游产物地址，账务恢复证据也不包含图片；若存储桶和供应商均无可取回产物，升级不能自动补回历史图片。

转存前先用 `image.DecodeConfig` 校验正的宽高及不超过 100,000,000 像素的上限，再执行 `image.Decode` 完整解码。仅有签名、只有合法头部但缺失像素、正文截断或解码失败的图片按 `image_result_invalid` 拒绝；不能只凭文件扩展名或头部尺寸将其视为可交付结果。

转存遇到上传、下载、超时等临时故障时，在单张传输重试之外再按 15 秒、1 分钟、3 分钟三档整体重试（`ImageTaskService.SetDeliveryRetryDelays`，生产装配启用）；对象键稳定，已上传的图片幂等覆盖，不重新生成。图片内容非法、超过大小限制或存储拒绝访问立即失败。重试期间任务仍为 `processing`，执行租约持续续期，任务硬截止时间相应加上重试窗口。

后台生成拥有独立的 30 分钟超时，图片转存预算为 2 分钟加重试窗口；仅内部异步上下文让上游脱离客户端取消时保留这一截止时间，普通同步请求语义不变。每实例最多受理 64 个尚未结束的异步任务（含排队、执行及存图），占满时新提交返回 503，不能通过快速获取 202 无限堆积原图与生成结果。现有用户/账号并发及排队限制仍在后台执行链生效；这是本机受理保护，不是跨实例持久队列。

提交及每次终态写入分别设置 24 小时结果保留期限，响应 `expires_at` 是当前记录的过期时间。PostgreSQL 中任务结果与 `media_tasks` 投影同事务提交，Redis 写失败不影响已保存结果；查询可直接从 PostgreSQL 返回。数据库终态写入短暂失败时，仅允许已受理且执行身份匹配的任务先保存在 Redis，由后台维护或合法查询补写数据库和列表。终态入库使用独立预算及有界重试，上传耗尽自身预算不应阻止保存终态。

每个新任务有 90 秒执行租约，执行实例每 15 秒续租；硬截止时间为生成预算加 3 分钟再加转存重试窗口，覆盖上传和收尾。后台每 15 秒限量检查遗留任务，失联或超过硬期限的任务记为 `failed / 503`，错误类型为 `execution_interrupted`，明确告知结果不确定且可能已计费。行锁内复核租约，多实例不能凭启动事件误判其他活跃实例；同一执行者稍后保存的真实结果可纠正维护器的中断判定。已完成结果不因普通重启或 Redis 数据丢失而丢失，过期结果记录定量清理，列表历史保留。

执行仍是进程内同步上游调用，不是可以安全重放的持久队列；未收到上游结果就退出时不能保证恢复图片。恢复程序不调用生成、不结算、不自动退款。升级前的 Redis 任务可以兼容读取并回填，旧任务没有心跳时使用创建后 32 分钟执行预算，不立即中止旧实例任务。PostgreSQL 与 Redis 同时持续不可写、或者进程在图片上传/结果持久化之前退出，仍可能无法找回结果；此时应核对错误及用量记录，不可承诺“所有故障下都续跑”。

## 图片对象保存与清理

后台“数据备份 → 异步图片存储”的“图片保存时间（小时）”控制新上传异步图片在 R2/S3 中的保存期限，默认 **24 小时**，允许整数 1–8760 小时。未保存过的后台配置回落到 `image_storage.retention_hours` / `IMAGE_STORAGE_RETENTION_HOURS`，缺省或 0 兼容为 24 小时。图片首次准备上传时固定到期时间，同一对象的传输重试不延长期限；后续修改设置只影响新上传图片。旧版本没有登记的桶内对象不追溯删除，创作台、备份和其他文件不受此配置影响。

迁移 `313_image_object_cleanup.sql` 建立独立持久清理队列。每次真实图片上传前，先登记确切对象键、绝对到期时间以及存储配置快照；登记失败不上传。S3 快照含凭据，使用 AES-GCM 加密，受理付费生成前必须检查清理表就绪、稳定加密密钥及存储读写删除能力；须显式配置并持久保存 `TOTP_ENCRYPTION_KEY`，包括只使用 YAML 配置 S3 的部署。新的本地快照以 `plain:` 前缀保存，清除 S3 凭据且只允许本地目标，不要求 TOTP 加密密钥；本地下载链接仍要求稳定 JWT 签名密钥。旧的加密本地记录与 S3 记录仍按原加密密钥解密，不能丢弃仍被旧记录使用的密钥。

清理循环随异步任务服务启动，每 15 秒检查已到期记录，单轮最多 100 个对象并有 45 秒总预算；每次只领取一个对象，使用 PostgreSQL 租约协调多实例。删除只针对通过原存储快照核对的完整对象键，不枚举桶、不创建或改写桶生命周期规则。已不存在的对象视为成功；网络、权限或数据库故障保留清理证据，按 1 分钟递增至最多 1 小时的间隔重试。因此正常情况下到期后由下一轮清理删除，故障和积压会推迟物理删除。

关闭异步生成、修改桶配置或服务重启不取消已有清理。恢复后仍使用首次上传时的桶和凭据，运维应保留对应凭据的删除权限及原加密密钥，直到旧对象清理完成。队列独立于短期任务结果，不因任务记录过期而丢失。队列包含加密凭据，数据库备份及加密密钥均须按敏感数据保护。清理失败日志只记录登记 ID 和固定错误分类，不包含明文密钥或签名链接；清理不触发重新生成，也不改变费用和用量记录。

任务查询结果仍保留 24 小时，图片保存期和任务列表历史独立。私有桶签名链接的有效期取配置签名期限与对象剩余保存时间的较小值，上传和重试不会让签名越过对象到期时间；公开地址依赖对象实际删除失效，外部 CDN 或客户端缓存不由本清理程序清除。若桶另有更短的生命周期规则，图片可能提前被桶删除。

主要代码入口：`service/image_object_cleanup.go`、`service/image_task_runtime.go`、`repository/image_object_cleanup_store.go`、`repository/image_storage_s3.go`、`repository/image_storage_local.go`。

## 本地目录存储

“异步图片存储”的存储后端可选 `s3`（默认，AWS S3 / R2 / OSS / MinIO）或 `local`（`image_storage.backend: local`）。本地后端把图片写入本机目录 `local_dir`（默认 `data/image-storage`，相对路径按进程工作目录解析），Windows 与 Linux 行为一致：路径统一经 `filepath` 处理，对象键拒绝绝对路径、反斜杠、冒号、`..` 及非规范写法；写入先落同目录临时文件、刷盘后原子改名，中断不会留下半张图片。`local_max_total_bytes` 限制目录总占用（0 不限制），超额写入按转存失败处理且不计费。

本地图片不直接暴露目录，下载走 `GET/HEAD /api/v1/image-files/*key?exp=&sig=`。签名为 HMAC-SHA256（对象键 + 到期时间），密钥由 `jwt.secret` 派生并与登录令牌用途隔离；`jwt.secret` 变更会使旧链接失效。链接有效期与 S3 签名规则相同，取签名期限与对象剩余保存时间的较小值。签名无效、过期或文件不存在统一返回 404，响应类型按真实字节嗅探且只放行位图。链接主机取 `public_base_url`（此时含义是客户端访问本站的地址），留空回落到 `server.frontend_url`；两者都为空时就绪检查失败，不受理任务。

配置 `local_max_total_bytes` 时，容量检查与写入在跨进程锁文件（`.capacity.lock`，`O_CREATE|O_EXCL`，Windows 与 Linux 一致）内执行，并以目录的实际占用为准：多实例共享目录按同一上限检查，覆盖同一对象只计“新 − 旧”的增量，不会重复累计或误报存储已满。锁文件保存持有者令牌，持有期间每 10 秒刷新时间；超过 30 秒未刷新的锁可被接管，释放前检查锁文件仍属于当前令牌。原子改名期间临时文件与旧文件会短暂并存，瞬时最多多出旧文件大小。

本地对象同样先登记持久清理再写入，到期由清理循环按确切路径删除；清理快照记录目录，切换回 S3 后旧文件仍会被删除，但下载路由只服务当前生效的本地配置。多实例部署必须让所有实例挂载同一共享目录，否则下载请求落到其它实例会返回 404。就绪探针在目录内写入、读回并删除随机文件。本地后端不需要任何对象存储凭证，保存设置时会清空 S3 字段。

<a id="async_image_idempotency"></a>
## 异步图片幂等提交

两个异步提交端点接受可选请求头 `Idempotency-Key`（去除首尾空白后最长 128 字符，超长返回 400），用于客户端在超时或断线后安全重试。请求指纹由接口类型（生成或编辑）与请求内容计算：JSON 及其它非 multipart 正文按原始字节；multipart 依序按字段名、文件名与各字段内容摘要计算，不受随机 boundary 影响，字段顺序或内容变化视为不同请求。

处理器在请求校验之后、存储探测与创建任务之前，按“API Key + 幂等键”查询 PostgreSQL 中未过期的任务：指纹与归属一致时返回原任务当前状态的 HTTP 202 及 `Idempotent-Replayed: true`，不探测存储、不创建任务、不生成也不预占或扣费；指纹不一致返回 409 `IMAGE_TASK_IDEMPOTENCY_CONFLICT`。没有记录时正常创建，幂等键与指纹写入任务记录和 `image_tasks.idempotency_key`（迁移 `326`），部分唯一索引 `(api_key_id, idempotency_key)` 裁决并发的同键提交，落败方取回胜出的任务且不启动执行。

幂等窗口等于任务查询记录的有效期（`expires_at`，创建及终态时各起算 24 小时）；过期后再次使用同一键时，仓储先清空过期任务占用的幂等键再创建新任务，旧结果仍按原规则清理。仓储不支持幂等查询时带幂等键的请求返回 400，不能静默忽略后重复生成。余额耗尽时，鉴权中间件对 OpenAI/Grok 分组带合法幂等键的异步提交（不含复合 Key 与智能路由）延后余额判断：处理器先按幂等键取回原任务；没有原任务时返回与中间件相同的 403 `INSUFFICIENT_BALANCE`，不创建任务也不执行，新任务不能借此绕过余额检查。同步图片与不带幂等键的提交仍在中间件直接拒绝。

<a id="async_image_billing"></a>
## 异步图片资金预占

标准模式的 OpenAI/Grok 异步 Images 在完整网关选组、选账号并取得并发槽之后，按请求数量和尺寸冻结固定图片费用，再调用上游。渠道 Token 图片与非 MJ 同步接口仍使用原有后结算；`simple` 模式不冻结资金。HTTP 202 只代表任务已受理，后台资金预占失败会将任务记为失败，且不发起生成。预占依赖新增迁移 `295_image_billing_reservations.sql`；缺少持久账本能力时拒绝执行，不能退回不受保护的后扣。

MJ 的一次生成已验证会返回四张图片，因此同步与异步入口都复用本账本，在最终账号映射确认 MJ 后按最多四张预占；出站仍是 `n=1`，不发起四次生成。只允许省略 `n` 或数值 `1`，参数限制也适用于渠道/账号别名。必须配置明确的按图/按次价格或分组尺寸图片价，不能因零 Token 响应走免费 Token 结算；当前尺寸缺价与显式零价严格区分，各尺寸报价只使用首次解析的价卡快照。已冻结较小图片预算的请求不能故障切换到需要四张预算的账号；返回服务不可用并按既有规则释放明确拒绝的预占。MJ 的 HTTP 408/5xx 视为上游生成结果未知，不能当成明确失败释放或切账号重发。有效产出按真实数量和冻结价格捕获，额外第五张、未知执行结果、进程中断及恢复继续遵守下述边界。

`auto` 在付款用户行锁内按适用订阅额度分摊基础金额，剩余基础金额按余额自己的倍率冻结；各订阅使用其套餐分组倍率，余额使用用户专属倍率或分组倍率。独立图片倍率默认同时作用于两种资金来源；开启[订阅倍率优先](routing_and_billing.md#media_subscription_rate_priority)后，各订阅可用自身套餐对最终分组的有效覆盖，未配置时仍用独立倍率，余额继续独立倍率。禁止用订阅侧的最终费用反推余额倍率。强制订阅必须足额覆盖整笔预占，余额不足的自动/余额模式整笔回滚；多个账号、Key 和实例共用同一付款用户锁。团队请求继续区分付款用户与操作成员。

独立的 `image_billing_reservations` 保存稳定请求 ID、资金与价格快照、状态和最终分配，不保存密钥、提示词或图片。它不随 24 小时图片结果清理而删除。报价保存各尺寸单价，以请求尺寸和数量预占；明确失败后的账号切换沿用首次报价，同一任务不能重复冻结。完成时按真实图片数量、尺寸和冻结价结算，少生成的差额退回；额外图片或实际基础费用超过预占上限进入待核对，不追加透支。调用期间调整价卡或倍率不改变已预占合同。

生成成功后的捕获与普通 `usage_billing_dedup`、Key/账号/团队统计在同一事务中完成，Usage Log 回填真实订阅和余额分配。捕获不再扣第二次余额；缓存使用失效后重读，不能再按消费金额减一次。重复捕获只返回原资金结果，不重复计数或通知。预占阶段不累计 Key/账号/团队消费，最终捕获才累计。

任务已预占且确认产图后，如果原上游账号被软删除，捕获仍按原合同完成用户扣款、Key/团队统计和同归属使用记录，只跳过已删除账号的额度统计，避免已生成图片的冻结资金永久卡住。该例外需先验证预占身份与金额，并核实账号确为同 ID 的软删除记录；不存在的账号、用户/Key/团队归属冲突仍拒绝，普通同步扣费也不放宽。

明确未发送或未受理的上游拒绝可以释放资金，释放幂等且不能撤销已完成捕获。错误包装必须携带图片尝试结果；普通 5xx 不能仅凭 HTTP 状态被当成明确拒绝。公开同步与异步重入共享最多两个不同账号各一次发送及首次固定截止，同号内部恢复不增加生成次数；安全换号只复用原预占，未知受理则保留资金待核对。传输中断、读取截断、成功响应却没有有效图片等无法确认上游执行结果时，停止自动切换账号重放，保留预占并标记 `reconciliation`。空结果不按请求张数补造消费记录。原生成维护器每 15 秒检查超期预占，缺少成功证据时只改为待核对，不自行退款或重新生图。默认资金期限 35 分钟；有执行截止时间时使用该截止时间加 3 分钟，不能通过删账本清除冻结。任务已进入失败终态后，由独立的[失败任务账务处理](#media_task_reconciliation)提供管理员决定和可配置超时释放，不改变原生成器的证据判断。

迁移 `307_image_billing_settlement_recovery.sql` 为预占保存安全结算证据。新任务确认图片输出后，先保存原结算命令和用量元数据，再捕获资金。捕获或使用记录保存失败时，维护器认领有证据的账本，按 60 秒递增至 15 分钟的间隔补偿；重试使用原预占价格、资金来源和真实数量，只补账务与同归属使用记录，不重新生成。日志费用取持久扣款回执中的订阅与余额金额之和，不能沿用首次估价或失败时的零额。恢复后失效余额、Key 限额与付款人及操作成员的鉴权缓存。

证据不包含密钥对象、关联账号对象、提示词、图片、上游响应、IP、UA 或会话。历史未知结果，以及数据库在成功证据落盘前持续不可写的任务，仍需核对上游和原账务；不得凭完成标记猜测费用。

<a id="media_task_observation"></a>
## 任务记录观测

`media_tasks` 是独立的 PostgreSQL 元数据投影，不持久化请求正文、图片 Base64、生成文件或视频下载地址；短期图片结果另存 `image_tasks`，旧视频完成产物地址保存为独立的 Redis 短期快照，新 Video 的结果另存 `video_tasks`，都不暴露在通用列表中。来源为：

| 来源 | 类型 | 状态更新入口 |
| --- | --- | --- |
| `async_image` | 图片 | 上述异步图片提交及后台结束 |
| `grok_video` | 视频 | Grok 创建/查询/编辑/扩展及数据库租约后台恢复 |
| `seedance_video` | 视频 | Seedance 原生创建/查询/删除及数据库租约后台恢复 |
| `video` | 视频 | 独立 Video 创建/查询/取消及后台持久恢复 |

以 `(source, task_id, api_key_id)` 唯一约束去重，保存创建、更新、完成及过期时间。并发更新使用单条 UPSERT，已经观测到的完成、失败、取消和过期终态不被迟到的处理中状态覆盖。异步图片以受行锁保护的 `image_tasks` 状态在同一事务内更新投影，允许同执行真实终态纠正 `execution_interrupted`，不允许迟到处理状态回退。未完成且超过 `expires_at` 的记录在查询时显示过期。视频供应商状态归一化为 `queued`、`processing`、`completed`、`failed`、`cancelled`、`expired`；HTTP 查询失败本身不能被当作生成失败。失败摘要使用固定分类文本，原始上游错误仍由现有错误日志或短期图片查询保存。

用户页面 `/media-tasks` 通过 `GET /api/v1/media-tasks` 和 `GET /api/v1/media-tasks/:id` 只能读取自己的任务，即使传入其它用户 ID 也不能越权，且不暴露上游账号 ID。管理员页面 `/admin/media-tasks` 使用同名 `/api/v1/admin` 接口读取全部任务，支持用户 ID 筛选。两种列表都支持媒体类型、状态、来源、模型、分页；个人入口中的管理员也只看自己。接口沿用面板 JWT/管理员认证与分页 envelope，返回 `Cache-Control: no-store`。

两种入口均提供 `GET /media-tasks/models`，返回统一 envelope 中的字符串数组。模型选项来自完整授权任务集合去重，支持媒体类型、状态、来源与管理员用户筛选，不受当前分页或已选模型影响；个人入口即使携带其他用户 ID 也只返回自己的模型。

列表模型下拉发送 `model_exact=true`，按完整模型名匹配，选择 `model` 不会混入 `model-pro`；不带该参数的旧客户端仍保留原有字面子串搜索。模型选项查询忽略当前模型以及 `model_exact`，避免选中后丢失其它选项。

管理员列表与详情额外返回安全的 `user` 身份摘要（`id`、`email`、`username`、可选 `deleted_at`），查询时关联当前用户资料，不复制完整用户对象或增加任务写入字段。用户筛选复用使用记录的管理员搜索接口，按用户名或邮箱搜索、选择后传递稳定用户 ID；模型使用项目可搜索选择框。页面沿用使用日志的名称优先、邮箱缩略回退与 `#ID` 展示，悬停可查看完整名称和邮箱；软删除用户显示删除标记，关联缺失时仍保留任务及用户 ID。个人接口不返回该摘要，页面也不显示管理员用户列。

列表是只读观测面板，刷新不会查询上游、触发扣费或重新生成。Grok/Seedance 通过 `legacy_video_tasks` 和 `LegacyVideoRuntime` 在服务端查询原账号、补写终态和幂等结算；升级仅导入最近七天已有任务记录，缺少原资金快照时更新真实状态并保留账务待核对。独立 Video 使用自己的后台持久轮询与幂等结算，返回 `video_billing` 费用快照，见[独立视频任务](video_tasks.md)。完整旧视频恢复契约见 [Grok](../interfaces/grok_upstream.md#grok_video_ownership)、[Seedance](../interfaces/seedance_upstream.md)。

`actual_cost` 和 `billing_mode` 按同用户、同 Key、同请求 ID 从使用记录关联。图片使用普通网关的 `client:<内部 ID>`，视频使用原有稳定任务结算 ID。费用为空表示尚未找到使用记录，不等于免费，也不能仅凭任务完成推断已扣费；明确零费用保留为零。智能路由最终分组、平台与管理员可见的账号优先取实际使用记录，模型保持提交时记录的名称。费用写入存在异步延迟，最终以既有使用记录与账务为准。列表同时返回 `billing_review`，优先展示真实预留状态及永久人工处理凭证；人工确认费用不伪造 Usage Log，GET 查询本身不触发扣款或退款。

独立 Video（`source=video`）在用户和管理员的任务列表、详情与预览中，金额统一四舍五入保留五位小数，例如 `0.70592980` 显示为 `0.70593`；视频单价和预留金额使用相同展示规则。非零金额舍入到零时显示为小于 `0.00001`，明确零与未确认费用仍分别展示。这仅影响显示，不修改接口数值、历史记录或账务结算精度，其它任务来源与使用记录保持原有精度。

Video 的账务状态与生成状态分开展示：`video_billing.status=reconciliation` 的未完成任务显示“待核对”，已失败或已完成任务保留生成终态并补充待核对提示；退款失败不能被展示为退款成功。账本确认 `released` 后费用显示“未扣费”，详情显示“预扣已释放”。已释放或已结算任务保存的历史预留字段显示为“原预留金额”，不表示当前冻结余额。这些展示在桌面、手机、详情与预览保持一致，不改筛选值或其它来源任务的状态含义。

<a id="media_task_reconciliation"></a>
## 失败任务账务处理

费用为空只表示没有关联使用记录，不能据此判断资金是否冻结。任务列表和详情通过 `billing_review` 读取原 `image_billing_reservations` 或 `video_tasks` 账本，区分待处理、已扣款、已释放、已过期、未预留和账务不可用；当前余额冻结、订阅额度预留与历史原预留金额分开展示。读取失败不显示零冻结，不开放资金按钮。旧 Grok/Seedance 后扣视频和没有预占账本的图片不能凭空退款。

管理员通过 `POST /api/v1/admin/media-tasks/:id/settlement` 提交 `action=charge|release` 和 1–500 字符的 `reason`。允许已失败、取消或过期且原账本仍为 `reserved/reconciliation` 的任务；额外允许 `source=async_image`、`completed` 但预占仍待核对的历史图片，以及 `source=video`、`completed` 且自动结算已转入 `reconciliation` 的视频（用量始终无法确认、扣费持续失败等，否则冻结会一直滞留），由管理员核实实际交付后决定扣费或释放；已完成视频仍为 `reserved` 时表示正在等待成品或取回探测，由自动流程按期限处理，不开放人工入口。两类操作都会复核仍存在的源任务真实状态及原账本，不能凭完成标记猜测费用。处理中、其它来源的生成成功任务、已捕获、已释放以及已有正数收费记录的任务不接受此操作。该人工入口不让成功任务进入自动过期退款，自动维护仍只处理失败、取消、过期三类状态。个人入口没有写路由，处理器及服务再次校验管理员。浏览器不能指定付款人、资金来源、价格或扣款金额。

`release` 将原余额冻结退回原付款人，并按原订阅窗口和重置代次释放额度；这是未捕获资金的释放，不是已扣款冲正。`charge` 由管理员核定整笔原预留金额，保留原订阅/余额分配，不使用当前价卡、不扩大扣款，Token 视频预扣也只确认原保证金额。没有预留的 Token 后扣任务不能据此收费。人工核定不伪造供应商 Token、图片张数或上游成本；永久决策表是该笔人工核定的账务凭证，任务记录显示明确金额，不补造普通模型 Usage Log。余额、Key/成员/平台额度以及日活动消费继续按原资金合同更新。

系统配置 `media_task_reconciliation_timeout_minutes` 默认 **60 分钟**，允许整数 **1–10080**。后台每分钟扫描最多 100 笔失败待处理账本，每轮有 45 秒预算；到期后执行与人工释放相同的资金事务，处理状态及媒体列表变为过期。期限从持久 `completed_at` 起算；缺少该时间的历史记录保守使用 `updated_at`，不会用创建时间使长任务刚失败就过期。设置从数据库动态读取，修改后下一轮生效，也适用于历史失败待处理任务；数据库不可读或旧配置非法时整轮跳过。该期限与图片在 R2 的保存期、结果查询期以及上游生成预算独立。已正常自动释放的失败任务不重复退款，成功、处理中、受理不明和缺少可操作账本的记录不进入此自动流程。

迁移 `315_media_task_billing_resolutions.sql` 建立每个媒体任务唯一的永久决定，保存动作、管理员、理由、原预留、核定金额、付款人与时间。事务先锁原付款用户，再锁媒体投影和源账本，复核身份、状态及截止时间后完成资金操作、审计和终态；失败整体回滚，同动作重放返回原结果，不同动作竞争返回 409。人工路径不等待自动路径已持有的用量去重键，避免反向锁死。重复扫描与多个实例不能重复释放；永久冲突短暂退避 5 分钟，避免堵住后续任务。

图片处理会终止原账务恢复并保留最终决定，迟到的自动捕获不能重扣，图片中断任务的迟到状态也不能覆盖人工过期投影。视频同时失效旧执行租约，原捕获/释放守卫拒绝终态重入；失败但已人工扣款的画布节点返回失败终态，不继续等待退款。已完成视频被人工释放后，画布同样返回 `failed / CREATIVE_VIDEO_RELEASED`，说明未扣费且预扣已释放，不再永久显示结算待核对。提交后使用独立上下文失效付款人、行为人鉴权以及余额/Key 限额缓存。人工核定和超时释放不调用生成、不保证上游没有实际消耗费用，也不追回已删除的图片。

升级前旧流程可能留下“异步图片已完成、预占仍为 reserved/reconciliation 且没有结算证据”的历史任务：结果已交付却从未扣费，自动恢复既不能凭完成标记猜测扣费，也不能无条件退款，因此不进入自动过期释放。这类任务在任务记录的账务核对中对管理员开放“核定扣款/释放”，由管理员按实际交付情况决定；金额与付款人仍完全取自原账本，决定与资金在同一事务内提交。

## 任务结果预览

个人和管理员入口的 `GET /media-tasks/:id/preview` 使用与详情相同的对象级权限，不需要用户提交生成任务的 API Key。响应只包含 `items` 白名单媒体项、可选 `expires_at` 和 `unavailable_reason`（`pending`、`expired`、`unavailable`）。媒体项包括 `url`、`media_type`，以及产物实际报告时才提供的 MIME、宽高、时长、字节数；不透传原始结果 JSON、提示词或上游错误正文。预览只读取现有结果，不查询上游任务、不触发生成、恢复、补写或计费。

图片预览通过任务的原始 `task_id + user_id + api_key_id` 只读 PostgreSQL `image_tasks`，再次核对 JSON 归属、完成状态和保留期，仅提取结果中的 HTTP(S) 图片地址。不调用可能补写状态的 `ImageTaskStore.Get`，不延长结果或对象存储签名 URL 的有效期；只有 Redis 中存在尚未补写的终态时，需等待正常维护流程完成后才可预览。

旧 Grok/Seedance 视频预览在合法状态查询、后台恢复或 Grok 内容下载观察到完成产物时，额外把直接媒体 URL 和少量数值属性写入 Redis，按来源、任务、用户和 Key 隔离，最多保留 24 小时。缓存不保存请求正文、响应正文或上游凭据，失败不改变原响应与结算。Grok 继续限制为既有允许的官方签名媒体地址，需带上游凭据的代理内容路径不可进入此缓存；Seedance 提取成功响应的 `content.video_url`。上线前的历史结果、未查询完成的任务、缓存丢失或不支持的媒体地址会显示不可用，不为补齐预览重新调用上游。

独立 Video（`source=video`）在签发票据及每次播放时都读取 `video_tasks`，核对任务 ID、原用户和原 Key，并要求生成状态为 `completed`、账务状态为 `settled`、存在完成时间且仍在完成后 24 小时内；已有 Redis 媒体快照不能替代这些检查。保留期已结束的合法完成记录返回 `unavailable_reason=expired`，与没有产物的任务区分。优先使用持久任务中的安全公共产物地址；没有 `VideoURL` 且冻结协议声明了凭据内容路径（内置 `openai_videos` 或模板 `content.mode=path`）时，也可为原任务签发播放票据。预览元数据与签票过程只读本地记录，不访问账号凭据或上游。

视频预览返回 256 位随机票据对应的本站相对地址 `/api/v1/media-tasks/preview-content/:ticket`，票据最长有效十分钟，且不超过任务与结果期限。该地址仅授权绑定任务的播放文件，支持 `GET`、`HEAD` 和单段 `Range`，不能指定任意下载 URL。每次播放重新核对任务及对应结果的归属；完成后禁用用户或注销会话不会即时撤销已签发票据，最长存在剩余十分钟的分享访问窗口。删除任务、任务/结果到期或 Redis 票据清理后访问失效；旧 Grok/Seedance 的结果缓存丢失也会使访问失效。

公共媒体下载使用公共目标校验和固定已校验 DNS 地址拨号，禁止内网地址、URL 内嵌凭据与环境代理，不转发 Cookie、JWT 或上游 Authorization。独立 Video 缺少公共产物地址时，实际播放请求才由服务端使用原账号凭据访问冻结地址下的固定 `/v1/videos/:upstream_id/content`；带凭据请求禁止自动重定向，跳转目标重新通过公共地址及 DNS 校验后以无凭据请求访问。凭据不进入票据、浏览器或公共 CDN 请求；图片和旧 Grok/Seedance 继续使用原有公共地址规则。

独立 Video 播放与站内 Key 内容入口 `/v1/videos/:id/content` 共用只读内容传输，不调用生成、任务状态查询、恢复或结算。两者分开鉴权，API 入口仍核对原 Key/原行为用户，面板入口使用上述短期票据；具体边界见[OpenAI 视频入口与内容](../interfaces/video_upstream.md#video_openai_content)。播放仅输出视频类型及有限内容头，不透传供应商错误正文或重定向地址；每次响应最多 512 MiB、最长两分钟，API 下载与面板播放共享本机最多 16 条同时下载流，票据入口继续使用公开接口 IP 限流。票据和媒体响应均禁止浏览器缓存、禁止 Referer 泄露；应用访问日志把票据路径替换为 `:ticket`，外部反向代理也应对该路由隐藏访问票据。Redis 若开启持久化或备份，其中短期视频访问地址仍需按私有业务数据保护；数据库投影不新增视频地址字段。

## 配置与上线

独立 Video 的预览元数据始终来自 `video_tasks`，不依赖 Redis 媒体快照，依然限完成后 24 小时；播放票据仍依赖 Redis。取得元数据不调用供应商，播放可按上述规则读取公共媒体或固定的上游内容路径。新表保存的供应商响应和签名媒体 URL 会进入数据库备份，应按私有业务数据保护。

- 数据库使用 `282_media_tasks.sql` 建立列表投影，新增 `283_image_tasks_durable_results.sql` 建立短期结果与租约，不修改已执行迁移，不改余额、订阅或渠道定价表。新应用正常启动时自动迁移。
- 管理后台“数据备份”页面新增“异步图片存储”。管理员可独立配置 S3，也可复用备份 S3 的连接和凭据，图片单独设置 Bucket/Prefix。配置保存在运行时设置中，其中 Secret 加密存储；查询脱敏，空 Secret 保留已有值，保存和测试沿用 step-up。没有后台覆盖时使用 YAML/环境变量中的 `image_storage`；后台保存后本机立即失效缓存，多实例最多约 30 秒更新。
- 存储连通性测试执行小对象写入、读取内容验证和删除清理，使用图片配置的 Bucket/Prefix；存储凭据必须允许这三项操作，不能只具备桶元数据读取权限。探针不生成图片、不调用模型或扣费；公开域名、CDN、浏览器访问规则仍需单独验证。
- 未配置公开访问地址时使用有期限的签名链接；签名期限只允许 1–168 小时（最多 7 天），旧配置中的非正数继续采用 24 小时默认值。后台保存和测试会明确拒绝超限期限，历史数据库设置及 YAML/环境配置在创建存储客户端前也会被拒绝启用；禁用配置和配置文件读取不会因此阻止整个应用启动。配置公开地址时，持有对象地址的人可以访问相应图片。管理员应按数据保留要求设置存储桶权限和生命周期。
- PostgreSQL 结果保留期、Redis 镜像 TTL、图片对象保存期和任务列表历史保留独立；短期结果表由维护循环清理，当前列表元数据没有自动清理任务。新上传异步图片由[持久清理队列](#async_image_object_retention)按配置到期删除，默认 24 小时；签名链接不能超过对象剩余保存时间。短期结果含图片访问链接，会进入数据库备份，按业务数据权限保护备份。
- 现有同步 Images、创作台、Gemini 批量图片接口不因异步图片开关而改变。长时间请求仍受上游/代理自身超时影响，异步接口解决的是客户端等待同一条连接的问题。

主要代码入口：`backend/internal/handler/image_task_handler.go`、`service/image_task.go`、`service/image_storage_settings.go`、`repository/image_storage_s3.go`、`service/media_task.go`、`repository/media_task_repo.go`、`handler/grok_media.go`、`frontend/src/views/MediaTasksView.vue`。

旧 Grok/Seedance 恢复依赖迁移 `306_legacy_video_tasks.sql`；新表保存安全计费与状态依据及实际扣费回执，不能通过删除恢复记录消除已发生的账务。
