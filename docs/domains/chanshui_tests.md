# 掺水检测

本文描述管理员通过 Chanshui 检测上游账号文本模型、手动与定时执行以及可选自动停用的边界。检测对象是**账号管理中的上游账号**，不是后台独立的渠道实体或分组。上级目录：[领域文档](index.md)。

<a id="chanshui_access"></a>
## 入口与配置

系统设置中的 `chanshui_enabled` 默认关闭，缺失、无效或读取失败均按关闭处理。只有管理员设置 DTO 包含该字段，公开设置、HTML 注入、普通用户菜单和路由均不暴露检测能力。总开关关闭时隐藏管理员侧栏和设置页中的检测入口，直接访问 `/admin/chanshui-tests` 会回到系统设置的功能开关标签。路由在管理员角色检查后读取私有设置，缺失或读取失败同样不开放；已经打开的检测页在刷新发现关闭时退出。配置和历史保留，重新开启后可查看；手动创建与定时提交需要开关开启，已经提交的任务继续查询，关闭开关同时阻止新的自动停用和自动恢复。

新增配置先选择平台，再列出该平台全部 `apikey` 类型账号；不按分组、价格、启用状态、调度状态或到期状态隐藏账号，OAuth 等其它类型不进入候选。平台仅用于浏览器筛选，配置身份仍由账号、模型与协议组成，创建后固定；同一账号可按模型和协议建立多条配置。模型候选合并账号映射键、最终白名单与已有平台内置目录；通配映射通过目录中的具体型号展开，每项均检查映射后的白名单与文本能力。无映射的 Claude 等账号仍显示平台候选，明确白名单排除的型号不会回填；未知平台不套用 Claude 默认目录，也可手动填写文本别名。目录仅提供候选，不代表已对该上游实测可用。保存及提交前检查账号显式白名单与模型映射，不用平台内置原生模型目录限制兼容文本别名；实际请求使用账号映射后的模型，不经过渠道、分组或站内 API Key 的路由映射。不支持图片、视频、音频和 System One 专用模型。活动任务存在时禁止修改或删除配置，全站最多 200 条配置，每配置保留最近 60 次记录。管理员页面以账号为一级标题，模型与协议配置为独立小节，直接展示 60 槽历史色块；空位不代表失败，点击记录查看详情，不同配置的历史不会混合。

检测直接使用所选账号自身保存的 Base URL 与 API Key，允许公网 HTTP/HTTPS 并保留原始协议、端口和路径，不自动升级或改投其它站点。持有自身 API Key 的子账号可诊断，但不会借用父账号凭据；缺少有效密钥、缺少兼容地址或地址不合法时保留候选并明确提示。已有代理或自定义请求头不再阻止选择，页面提示远端检测直接访问公网地址、不会复用本站代理或额外头。平台本身不作为拒绝条件，但远端仍仅支持 Chat Completions、Anthropic Messages 和 OpenAI Responses 文本协议，纯媒体和特殊原生协议不因此变为受支持。浏览器候选接口只返回账号名称、编号、平台、类型、可用原因、诊断提醒和模型列表，不返回账号凭据或完整账号对象。账号 URL 与密钥由服务端发送给 Chanshui，远端会向该上游发起多项模型请求；会产生上游用量，但本模块不创建站内用户账单，不需要管理员的站内 API Key。页面明确展示此边界。

协议可指定 Chat Completions、Anthropic Messages、OpenAI Responses，或“跟随账号与模型”。自动模式优先使用账号固定协议、OpenAI 强制文本协议或 OpenCode 模型规则，再对未固定的兼容模型选择协议；提交前解析为明确协议，并以同一协议选择分协议地址，不交由远端重新猜测路径。显式协议只验证该次选择，不修改账号已有设置或正常网关路由。分协议地址优先于通用地址；已有其它协议地址但缺少当前协议时不回退供应商默认站点。未知或原生专用平台必须明确保存兼容地址，不能将其密钥发送到默认 OpenAI 地址。

可选板块为模型指纹、注入大小、缓存读写、工具调用、联网检测、知识截止日期、思维链回传和推理表现。默认全选，思维链单独检测只支持 Claude 模型。单请求超时默认 360 秒、范围 10–600 秒；定时默认关闭，间隔默认 60 分钟、范围 5–10080 分钟。按掺水自动停用必须包含指纹板块；低分阈值可留空关闭，范围 0–100，单独知识截止日期不计分，不能配置低分停用。`auto_recover` 默认关闭；开启必须同时启用配置、定时检测、指纹板块以及至少一种停用规则。

<a id="chanshui_execution"></a>
## 异步执行与恢复

参考 [Chanshui API 文档](https://chanshui.dev/docs) 与其公开 OpenAPI。客户端仅访问固定 `https://chanshui.dev/api/v1/audits`，POST 创建、GET 按合法远端编号查询；不跟随响应中的任意 URL 或 HTTP 重定向，不自动重放创建请求，响应上限 4 MiB。提交前验证上游 HTTP/HTTPS URL、禁止内网目标并重新核对 DNS；不能因输入错误把凭据发送到不同上游地址。

远端限制同一出口 IP 每 60 秒创建一次。本站所有实例通过 PostgreSQL 提交槽共用这个间隔，争用者排队；同配置只有一个活动任务。两个后台工作者每五秒领取任务，数据库租约为两分钟、单次编排最多 75 秒；结果持久化使用独立的有界 15 秒上下文。工作者随 Wire 启动，关机先停止工作者再关闭基础设施。

发送前先持久化 `submitting`。创建成功后保存远端编号，之后只 GET 查询；进程重启时没有编号的 `submitting`、网络中断或无法确认受理的 5xx 记为 `unknown`，不自动再创建，以免产生重复用量。只有明确 429 拒绝受理允许重新排队。管理员手动检测允许诊断已停用、暂停调度或已过期账号，不改变其状态。任务内部记录 `trigger=manual/schedule`；通常定时仅选择启用、可调度且未过期的账号，并在实际提交前复查；只有本功能持有有效停用所有权、且已开启自动恢复的账号可以在停用后继续定时复测；旧版缺失 trigger 的任务按定时约束保守处理。排队等待期间关闭总开关或修改凭据/地址会阻止旧配置提交，停用、暂停调度或到期会阻止定时任务继续提交。远端 404/410、返回过期时间或本站 24 小时观察期限到达均明确结束，不重新发起检测。

轮询短暂故障可退避后继续 GET。写回必须满足任务租约令牌和有效期，旧工作者不能覆盖新持有者；远端编号只存服务端，不进入管理页面或报告。历史摘要与详细报告分列，列表用一次批量查询为各配置读取最新 60 条安全摘要，配置查询加历史查询共两次 SQL，不读取完整报告；详情按需单独加载。

<a id="chanshui_decision"></a>
## 结果与自动停用

执行状态与检测结论分开：任务完成不代表模型正常。指纹结论只有 `clean`、`adulterated`、`unknown`，按远端官方归因规则正规化；至少三个有效样本、非低置信度、可识别的模型基线和完成的指纹探针才参与比较。未知模型、缺少基线、探针失败或低置信度保持未知，不能当作明确掺水。

总分取远端 `total.score`，为所选计分板块归一到 0–100 的得分，不是 IQ 单项。远端会把部分缺失或出错项计为零，因此只有所有适用项已知、证据完整、分值合法且探针完成才设置 `score_complete=true`。缺失项和异常分数不能用于低分停用，也不能用于恢复调用。上游已结束但探针仍为 `queued` / `running` 时明确显示该项未执行或未完成，推理题缺失按题数说明；不把未执行题目当作答错，不擅自移除已选择的板块。旧记录详情根据已有安全报告展示同样原因，不改写历史分数或处置结果。详情只保存固定字段、有限数值和本地安全文案；不保存任意上游错误、题目、模型回答、HTML、密钥或地址，不使用富文本执行报告内容。

自动停用默认关闭。完成的有效结果满足“确认掺水”开关或完整得分低于阈值时，才可停用所选账号；网络故障、超时、部分结果、无效分数与未知指纹不触发对应处置。终态、账号 `status=disabled`、`schedulable=false` 与调度 outbox 在同一事务中提交，刷新本实例缓存并通知其他实例，不改渠道、分组、余额或定价。

最终事务重新检查总开关、配置版本、规则、账号身份和当前状态。账号配置指纹及数据库维护的专用配置代次保护检测期间的凭据、地址、映射和状态变更；管理员停用再启用也会推进代次，旧结果不能重新停用。普通用量和最后使用时间更新不推进此代次。事务等待后再次校验租约，失效时整个处置回滚。已完成记录的重放不再执行停用或恢复。默认仍需管理员重新启用账号；只有显式选择以下恢复规则时才自动恢复。

## 自动复测与恢复调用

只有开启恢复规则后的新自动停用，才可建立 `chanshui_account_holds` 所有权记录，绑定停用后的账号配置代次。建立时该账号所有启用且具有停用规则的保护配置都须开启自动恢复、定时检测和指纹板块；任一配置未满足则仍执行停用，但不建立无望恢复的付费复测循环，动作原因提示需人工恢复。

保护配置及其版本固定到 `chanshui_recovery_checks`，所有模型都必须在本次停用后得到明确 `clean`、完整有效的总分，并达到各自原停用阈值（没有阈值时仍需完整有效分数）。只有全部保护模型通过、且没有其它正在进行的保护模型任务时，才在事务内将账号恢复为 `active` 与可调度、清除本功能停用原因、删除恢复记录并发送调度更新。每次重新测试会先清除该模型过去的通过标记；错误、未知、掺水、部分结果或未达阈值均保持停用。

人工停用的账号、旧版停用记录和不属于本功能持有状态的账号不会自动恢复。账号身份、状态或配置代次变化，以及任一账号检测配置的新增、修改、删除，会使旧恢复资格失效；管理员显式提交账号状态或调度开关时，即使值相同，也会在同一写事务推进内部代次以撤销旧恢复资格，后台普通更新不冒充管理员意图；不会用旧报告覆盖人工决定。过期账号不自动恢复。定时创建、手动创建、配置维护和结果处置统一按账号锁、配置锁排序，防止新检测排队与最终恢复之间的并发窗口。恢复与停用共用租约、版本、开关复查及调度 outbox 的事务保证。

列表的 `recovery_pending` 表示当前存在有效的复测恢复资格；任务动作 `recovery_pending` 表示继续停用等待保护模型达标，`recovered` 表示已经恢复调用。`auto_recover` 是配置规则，两个运行状态不由客户端写入。

## 存储与接口

迁移 `317_chanshui_tests.sql` 创建配置、执行记录与全局提交槽，并维护账号的内部配置代次。迁移 `318_chanshui_account_recovery.sql` 添加默认关闭的恢复规则、账号停用所有权与保护模型复验记录，不接管历史停用状态。凭据仅保留在原账号，执行记录保存不可逆配置指纹及内部版本用于比较，不复制明文。升级后默认关闭检测，不创建历史补测或改变已有账号状态。

接口均位于 `/api/v1/admin/chanshui-tests`：GET/POST 配置，GET `/targets`，PUT/DELETE `/:id`，POST `/:id/run`，GET `/:id/runs` 和 GET `/runs/:id`。路由组管理员中间件与每个处理器的角色检查共同保护全部入口，不提供普通用户投影。总开关沿用管理系统设置 GET/PUT，省略字段保持旧值。

主要实现：`internal/pkg/chanshui` 固定客户端与结果归一，`internal/service/chanshui_service.go` 编排，`internal/repository/chanshui_repo.go` 事务，`internal/handler/chanshui_handler.go` 权限入口，前端 `views/admin/ChanshuiTestsView.vue`。相关边界：[账号维护](../operations/account_maintenance.md)、[降智检测](intelligence_tests.md)、[配置边界](../interfaces/configuration.md)。
