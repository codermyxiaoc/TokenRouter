## 任务生命周期

Video 分组只绑定 Video API Key 账号。统一 `/v1/video/generations` 与 `/v1/videos` 复用相同任务和账本，厂商 JSON 的 `input`、`parameters`、`content`、参考媒体及扩展参数继续传给所选端点；原生入口使用相同状态机并保持原生响应。新 `/v1/videos` 向客户端投影四种状态，受理不明仍附加原任务状态而不改变预算处理。同一模型可允许多个上游端点，创建时按入站协议和配置集合选择，两个 OpenAI 入口必须分别明确启用 `compat`、`openai_videos` 且符合模型绑定，不回退到原生端点；未获准请求在建任务和预扣前拒绝。任务保存实际选中的端点，后续配置改变不重选已创建任务的查询、取消或计费协议。不会根据模型字符串猜测供应商。

生成前先验证权限与价格、选定账号，保存 `video_tasks` 的本地 `vid_…` ID、用户/Key、分组、账号及非敏感路由快照，再原子建立预算记录；Token 模型关闭预扣时该记录的初始预留金额为零，终态仍须实际结算。状态由 `prepared`、`submitting` 进入 `queued`/`processing`，最终为 `completed`/`failed`/`cancelled`。统一接口使用本地 ID，原生接口保留供应商 ID，`X-Video-Task-ID` 响应头关联本地记录。查询始终核对原用户和原 Key；同协议原生 ID 在不同账号间歧义时返回 409，绝不广播查询。

可选 `Idempotency-Key` 最多 128 字符，在同一 API Key 下唯一。相同原始正文和路径返回已有任务，不同字节返回 409；JSON 空格或键顺序变化也视为不同请求。原生重复提交重放保存的创建包，不拿查询包代替。每账号未完成任务上限在数据库账号级事务锁内检查，不被多实例并发绕过。上游已明确完成、失败、取消或过期的任务不再占用生成容量；过期任务的费用仍保留待核对，不因释放容量自动退款。受理不明、排队和处理中任务继续占用容量。本地任务尚未创建时，容量拒绝可以释放账号槽并重选其它合格账号；已经预扣后的换号须遵守下述同任务事务规则，不能另建任务或再次预扣。

创建禁用自动重定向；3xx 不向客户端透传 `Location`，防止客户端再次提交。原 HTTP 状态、正文和已取得的任务归属继续保存；3xx 本身不能证明未受理，不按无 ID 的 4xx/5xx 退款规则处理。客户端断开后，已开始的受理与归属保存使用有截止时间的独立上下文继续收尾。完整收到明确未受理的错误且没有任务 ID 时，可以在同组、同端点的其它合格账号上重试：默认最多换号三次，正数 `gateway.max_account_switches` 覆盖该值且最多十次。所有创建尝试共用 `gateway.video_create_timeout_seconds` 预算，默认 180 秒；首次提交以及换号重试都在实际 POST 前检查客户端取消。选账号、迁移及保存期间发生取消时，停止发送并释放尚未提交任务的原预算。已开始发送的请求仍独立收尾，不能因断连推断未受理；响应状态、任务归属保存及结算收尾使用独立有效上下文，不复用已到期的创建上下文。参数与审核错误、通用 internal error、HTML 网关页、超时断流、已有或冲突任务 ID 不允许重提。规范响应中的受理/成功状态、产物或正数用量即使没有 ID，也优先阻止重提，退款仍按原规则处理。5xx 仅接受结构化的服务不可用、过载或明确未受理等拒绝语义，仍依赖上游正确报告受理结果。

换号先保存拒绝响应，再在数据库事务中验证有效执行租约、任务未结算且尚无上游 ID，并锁定目标账号容量。原任务 ID、幂等键、价卡、用户倍率和资金预扣保持不变；仅迁移实际账号、上游模型/端点快照和账号成本倍率，保留安全的拒绝尝试摘要。协调器及事务仓储都要求端点、参数转换 profile、时长、精确尺寸、计价分辨率及参考素材计数一致；空 profile 与 `passthrough` 等价，H3 参数转换账号不能与透传账号互换。事务提交结果不明时停止发送；迁移后的 `prepared` 状态若崩溃，由恢复器释放原预算，不补发生成。完成时按最终账号记录成本和用量，只捕获一次用户费用。

部署时外层反向代理与客户端超时应覆盖创建预算及收尾时间。网络层提前断开不等于未受理；客户端重试应复用同一 `Idempotency-Key`、原始路径与正文，避免另起任务造成重复生成。这里不自动修改现有反向代理配置。

不满足安全重提条件或重试耗尽后，创建请求完整收到 HTTP 4xx/5xx 且没有上游任务 ID 时仍按失败释放预算，包括 408、502、503、504；这是平台承担上游可能已经受理成本的退款规则，不代表已经证明上游未生成。响应中的明确失败或取消终态同样进入释放流程。错误响应携带任务 ID 时必须保存归属，继续原账号查询；不能因 HTTP 错误丢弃 ID 或重新生成。MiniMax 的顶层 `TaskId` 按字符串受理 ID 处理；该字段若为数字、布尔值、对象或数组且没有其它合法 ID，则属于不可解析的受理证据，保持核对，不进入上述退款路径。

网络中断、正文读取失败、成功响应缺少任务 ID 等仍无法确认创建结果，任务进入 `submission_unknown` 并保留预算待核对；不自动换账号或重提。查询 HTTP 失败只退避重查，不能按上述创建退款规则处理。恢复器会重新解析旧任务保存的原始创建响应；新识别出合法受理 ID（例如 MiniMax 的 `TaskId`）时继续原任务查询，符合创建退款规则时保存为失败，再复用正常资金事务幂等释放。原始响应和历史预留金额保留，不直接改写余额或冻结字段。保存失败状态或退款事务失败时留待后续恢复，不宣称已经退款。

明确的创建超时在没有任务 ID、HTTP 状态、原始响应包、产物、上游状态或用量证据时，按首次持久化的超时起点等待 15 分钟，再持久化失败并调用正常 `video_release` 事务退回预留；不重发生成，可能已被上游受理的成本由平台承担。正文读取超时及已经取得 HTTP 响应后报错均归入响应故障，不能进入此自动退款路径。已有 ID、冲突或非法 ID 原包、成功缺 ID 原包继续保留核对。该规则同样处理本版 `submitting` 进程中断：必须存在有效持久化的提交开始与截止时刻，从原截止时刻计 15 分钟；进程在取得响应但尚未落盘时退出也属于无持久响应证据范围，由平台承担成本。旧版 `submission_unknown` 没有故障分类、或旧 `submitting` 没有提交时点的记录不自动推断为超时，需要人工核对。轮询、重启和 `updated_at` 更新不会延长核对窗口；退款或后续投影失败可继续恢复，幂等账本防止重复退款。

每实例每五秒最多领取八个到期任务，使用 `FOR UPDATE SKIP LOCKED`、三分钟恢复租约及写入 token 隔离执行者。创建租约至少为三分钟且覆盖创建预算另加 30 秒收尾，默认 210 秒；状态保存与安全换号均不会把长创建租约缩回三分钟。单次恢复预算 90 秒，只查询原账号、推进状态或补结算，绝不补发 POST。`prepared` 中断可释放；`submitting` 无持久响应证据按上述受限的超时/中断规则处理。取消只开放已支持协议，HTTP 200 本身不等于已取消，只有明确取消状态或适配器确认的空成功包才释放。终态不被迟到的排队包回退。上游过期但成本不明时转待对账，不直接退款。

查询和取消响应中的规范任务 ID 必须与冻结的上游任务 ID 一致；原生任务数组出现其他任务时整包拒绝，不通过只清空状态来保留外来用量、媒体或原始正文。字段真正缺失的合法查询包仍可处理。身份冲突按查询失败退避，保留原状态、原包和预算，不触发扣费、退款或重新生成；取消返回安全错误。原生响应重放和媒体读取也复核已存原包，已知身份冲突不会继续回传或播放；此防护不自动修改历史账务。

创建包同时给出不同的有效任务 ID 时，受理归属存在歧义，不能任选一个自动查询，也不能当作完全无 ID 的错误退款。任务保存内部诊断包并进入受理不明/待对账，首次响应与幂等重放均返回安全错误，不对外暴露冲突正文；预算保留，后台不重提或自动结算。

## 预算与结算

`yezonghui_v1` 复用本章全部账务事务：发送前由独立协议提取显式时长、分辨率和参考图数量，再冻结价卡。比例 `size` 不参与分辨率匹配；参考图短期链接不参与原请求幂等摘要，重复查询、恢复和下载不产生新费用。完成没有直链时使用原账号内容端点；缺少 Token 不伪造用量，异常维度继续待核对。接口及后台查询节奏见 [Yezonghui 视频兼容](../interfaces/video_upstream.md#video_yezonghui)。

支持 `video`（按秒）、`video_token`（每百万输出/完成 Token）和 `video_per_request`（每个成功任务一次）。价格按模型和分辨率匹配，每档只有一个单价，有无参考视频使用相同价格。480p、720p、1080p、768p、2k、4k 等档位不互相降档。缺价阻止生成，显式零价才免费；没有可靠 Token 用量时不能用时长估算或改按秒计费。参考图片仍可按独立固定附加费收费。可美协议的零 Token 占位保持未知，Vidu 未返回 Token 不推算为零或从秒数折算；适配后的实际发送参数决定输入维度，适配方案不改变价格单位、倍率或账务幂等键。

按次模式使用独立的 `request` 单位，任务提交时预留一次视频费用及固定参考图片附加费，成功后只结算一次，不乘时长、Token 数或产物数量。失败或确认取消释放预留；重复提交同一幂等任务、轮询、恢复和下载不会新增扣费，受理不明仍保留预算待对账。按次任务不要求可信时长或 Token；只有兜底价且没有分辨率矩阵时可省略分辨率，有矩阵时仍要求明确分辨率，避免省略参数绕过高价档位。新模式复用现有持久账本，无需迁移旧价格或任务；已受理任务继续使用原模式。

任务冻结模型单价和来源。跟随分组时沿用套餐对该组的倍率及用户余额专属倍率；独立视频倍率默认同时用于两类来源，不再叠乘组倍率。开启[订阅倍率优先](routing_and_billing.md#media_subscription_rate_priority)后，订阅可使用自身套餐对最终分组的有效覆盖；未配置时和余额部分继续使用独立倍率。是否允许套餐覆盖随 Hold 保存，后续分组修改不能改变任务原规则。修改模型价卡不改变已受理任务的单价；按秒、按次及旧任务保留原资金分配倍率，新 Token 预扣及后结算任务按下文在终态分配订阅。

预留复用既有订阅/余额、Key 总配额及 5h/1d/7d 限额、团队成员额度事务。按秒模式保持按请求时长及实际秒价预留，自动时长须配置 `video_max_duration_seconds`。账号不再提供 `video_max_output_tokens`，新任务忽略遗留值，保存账号时清理此字段。升级前已受理任务继续按自身持久快照结算，不迁移其预留或幂等身份。预算不注入厂商参数或截断真实用量。

Token 模型通过 `video_token_prepay: {"price_per_second": 0.3}` 显式开启固定秒价预扣，省略或 `null` 表示关闭。开启时预扣 `请求秒数 × 固定预扣秒价 + 图片固定附加费`，两部分都不乘渠道、分组、视频独立、套餐或余额倍率。自动/未知时长使用账号明确配置的时长预留上限，缺少上限则拒绝提交。8 秒、7 张图、前 5 张免费且每张 0.15 的示例预扣为 `8 × 0.3 + 2 × 0.15 = 2.70`。预扣金额和秒数单独冻结，不能用上游实际时长反推。

预扣 Token 任务完成且取得可信用量后，在同一资金事务中先按原窗口及重置代次退回原预占、解冻余额，再按真实 Token 基础成本及固定图片费分配当前可用资金；实际费用高于预扣可补扣，低于预扣退还差额。此过程与任务锁、用户锁、Key、团队及平台额度检查原子提交；任一步额度或资金不足，原预扣和所有临时变动均回滚，任务保留待对账。预扣只保证固定金额，不固定终态使用哪笔订阅；指定订阅失效时不能挪用旧额度或改成余额付费。最终订阅及其套餐覆盖倍率按终态资格选择，组/余额和独立视频倍率沿用创建快照。

关闭 Token 预扣时，任务仍持久化延迟计费标记、资金模式和指定订阅、组/余额倍率及价卡，初始不冻结资金或预占额度；完成后同样按可信用量和当前可用资金原子结算。失败和确认取消不扣费；未知受理与缺失用量继续保留任务。金额为零不能用于推断模式；旧任务不会被自动转成延迟计费或新预扣模式。

参考图片附加费使用创建时冻结的计数和固定单价，视频费用与附加费分别分配但仍在同一预留、捕获或释放事务中执行。图片部分倍率固定为 1，也可按原 Key 资金模式使用订阅和余额；视频倍率为零不免除图片费。订阅/余额混合分配保留费用组件，结算退差额不能把视频预算和图片预算互相挪用。Token 模型关闭预扣时图片费也不提前冻结，随最终视频用量一起结算；没有可信视频用量时不单独收取图片费。显式零视频价仍应收取已配置的图片费。失败及确认取消释放两部分，旧任务未配置附加费仍按原规则处理。

捕获与释放同时由任务行状态和账务幂等键保护。完成捕获实际费用并退回差额，失败或确认取消释放；账号成本只在捕获事务累计一次。Video 额度回退失败整体回滚，交恢复器重试，旧图片行为保持不变。

每个预占订阅保存实际日/周/月窗口、各窗口的手动重置代次及当时是否有限额。首次激活空窗口也可正确退回；退款同时匹配窗口起点和代次，管理员同日清零后即使日窗口起点不变，旧任务也不能减掉新用量。Video 用户平台额度只统计余额部分，在数据库事务内预留/检查/退差额，通用平台结算累计会跳过 Video，避免重复计数；所有平台均停用 Redis 增量和绝对快照刷回。日/周沿用站点自然日/周，月沿用 30 天滚动窗口；平台退款也精确匹配原额度行、窗口及代次，避免手动重置后归一化回原日/周起点时误退。代次只在显式手动重置的原事务中推进，不改变自然窗口、重置次数或旧图片结算规则。

账务已提交而使用记录暂不可写时，后台仅补同一 `video_capture:<ID>` 日志和列表投影，不再次扣费。任务记录的 `video_billing` 显示单位、分辨率、单价、Token/时长、预留金额、实际金额和结算状态；遗留参考视频标记不作为价格条件展示。配置图片费时补充输入张数、免费张数、计费张数和固定单价，只有账务已结算才显示实际图片费。Token 预扣任务还展示冻结的预扣秒价及预扣秒数，与最终时长和实扣金额分开。非终态待对账任务在面板显示“待核对”，已有失败或完成状态则保留并附上待核对提示。只有账本 `released` 才显示“未扣费 / 预扣已释放”；已释放或已结算任务的历史预留显示为“原预留金额”，不代表仍在冻结。金额缺失不等于零。使用记录分别保存视频输出费与固定图片输入费，合计与账本实际扣费关联。

受理不明、缺用量、价格维度不符、真实费用无法通过资金或配额检查会显示待对账；按秒及升级前旧 Token 上限任务仍保留超过预留待对账的规则。单任务 Token 用量或视频秒数超出现有使用记录的 32 位整数范围也会在扣费前转待对账，避免扣费后无法写入记录。长期停机导致耗时遥测越界时省略该遥测，不阻断正常结算。上游可查询的用量可由后台补齐；没有上游 ID 或可信费用时仍需要运营核对。当前没有在面板提供管理员强行补写 Token、改价或解除未知预算的操作。

完成响应的 `seconds`/时长或 `size`/分辨率存在格式错误、冲突时保留任务归属并进入待对账，不沿用创建参数扣费。后续恢复必须取得明确有效的时长和分辨率，Token 模式还须取得可信 Token；只返回“已完成”而缺少元数据不能消除先前错误或价档冲突。合法实际时长小于预留时按原价卡结算并退差；不对历史已结算任务自动重算、补扣或退款。

显式 Seedance 官方方案在预扣前按有效帧数换算小数秒，完成时按可信帧数和帧率结算；旧原样与可美合同保持不变。已持久化为完成但尚未结算的官方帧数任务，在捕获前重新解析原始响应，并先保存校正后的用量；保存失败不扣费，防止进程恢复后仍沿用旧解析器留下的较短请求时长。历史预扣不足仍按原资金保护进入待核对，不能强制扩大扣款；已结算/已释放任务不重新计算。完整协议与参数要求见[版本化协议适配](../interfaces/video_upstream.md#video_adapters)。

Vidu 明确缺作品或作品地址属于产物暂缺，不等同于计费维度冲突。同一任务后续补齐唯一作品时，可以使用原任务冻结的可信维度完成结算；按次价不要求无关时长。恢复须保留真实维度异常，Token 模式仍不能以缺失用量结算；具体白名单及协议边界见[版本化协议适配](../interfaces/video_upstream.md#video_adapters)。恢复继续使用原捕获幂等键，不新建任务或重复扣费。

使用记录按任务历史快照补充单位、精确时长和参考图片费用，兼容旧视频记录而不推测未知单价，详见[视频用量计价展示](routing_and_billing.md#usage_video_pricing)。

<a id="video_task_storage"></a>
## 数据与运行

`video_tasks` 保存状态、账务和路由快照、供应商响应及媒体 URL，不保存 API Key 或原始提交正文。显式协议适配的新任务保存版本二目标及固定协议 ID；原任务继续使用版本一。协议决定查询路径与响应事实解析，包括可美的响应结构和 Vidu 的创建操作与产物查询；版本二清空并隔离旧 `openai_profile`。账号端点、模型覆盖、Base URL 和操作路径变更不会迁移在途任务，也不改动冻结报价、预扣和退款。详见[版本化协议适配](../interfaces/video_upstream.md#video_adapters)。供应商响应可能回显业务内容或签名地址，数据库和备份须按私有数据保护。`media_tasks` 只是授权展示投影，不承担账务归属；目前两者没有自动删除任务的策略。

独立 Video 的面板预览在签票和每次播放时始终读取持久任务，复核任务 ID、原用户、原 Key、`completed` 与 `settled`，并要求完成时间存在且未超过 24 小时；Redis 媒体快照不能绕过这些检查。签票只读本地元数据，不访问账号凭据或供应商。即使没有公共产物地址，只要冻结端点为 `openai_videos`，也可签发最长十分钟且不超过结果期限的任务专属票据。播放票据仍依赖 Redis，并沿用对象权限和公开接口 IP 限流。原生查询结果保留与面板播放期限互相独立，旧 Grok/Seedance 的公共地址预览规则不变，新链路不依赖图片 S3 开关。

API Key 的 `GET /v1/videos/:id/content` 与面板预览票据分开鉴权，共用只读内容传输，只读已完成且已结算任务。无直接媒体地址时，服务端使用原账号凭据请求冻结地址下的固定 OpenAI Videos 内容路径；凭据不进入票据或浏览器，公共媒体及重定向下载不携带上游凭据。两种入口共享单段 Range、512 MiB、两分钟和本机最多 16 条下载流限制，不进入轮询、生成、恢复或结算。流式内容与凭据隔离规则见[OpenAI 视频内容接口](../interfaces/video_upstream.md#video_openai_content)。

`ProvideVideoTaskService` 启动恢复循环，Cleanup 在关闭数据库前幂等 `Stop`。迁移 `289_video_token_pricing.sql`、`290_video_tasks.sql` 和 `291_video_quota_reset_generations.sql` 建立视频价格、任务和内部重置代次；`292_video_image_input_pricing.sql` 为渠道价卡增加可空图片附加费 JSONB，旧行默认关闭，分组沿用原价卡 JSON。`293_video_fallback_and_token_prepay.sql` 增加可空兜底价及 Token 预扣 JSONB，旧价卡默认关闭。不修改已执行迁移。独立视频预算当前要求 standard 模式，simple 模式旧平台语义不变，Video 提交明确拒绝。

主要验证入口：`video_task_service_test.go`、`video_submission_retry_test.go`、`video_submission_timeout_test.go`、`video_submission_contract_test.go`、`video_task_billing_integration_test.go`、`video_task_retry_integration_test.go`、`video_task_submission_lease_integration_test.go`、视频协议及价格测试。隔离 PostgreSQL 覆盖并发预留/捕获、重复结算、捕获与释放互斥、订阅及平台原窗口退款，以及同周期手动重置后旧任务退款和重置事务回滚；换号回归验证一次预扣、最终账号成本、并发迁移互斥、目标容量、参数合同与失效租约拒绝。长租约回归覆盖创建期间不可抢占、到期单恢复者接管与并发退款一次生效。真实供应商生成不属于离线回归；数据库持续不可写，或有响应证据但不能恢复任务归属时仍需要人工核对，不能承诺所有故障都自动恢复产物。
