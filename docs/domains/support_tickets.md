# 工单

> 上级目录：[领域文档](index.md)

## 生命周期与权限

工单独立于团队，始终归创建用户所有。用户可创建、查看、回复、撤销和完成自己的工单；管理员可以查询所有工单、修改优先级、回复、完成和撤销工单。工单不再分配处理人员，界面和 API 均不提供接单或处理人员字段；每条消息仍保留实际发送者及客服身份。正式类型为咨询（`consultation`）、财务（`financial`）和技术（`technical`）。财务工单可以关联当前用户自己的支付订单，也允许不关联；其他类型不能关联订单。详情只暴露必要订单摘要，不返回支付提供商快照。

创建及用户回复后状态为 `pending`（待客服回复）；工作人员回复后为 `waiting_user`（待用户回复）。列表、详情及状态筛选使用同一组回复对象明确的标签，不把打开详情当作已经回复。协议值保持不变，已有工单直接使用新的显示文案。`completed`、`cancelled`、`expired` 为终态，不再接受回复。自动过期只检查等待用户回复的工单，按最近一次工作人员回复时间计算，用户回复会停止该轮过期计时。后台每分钟检查一次，条件更新与回复的行锁避免并发覆盖。

完成或撤销时，在同一行锁事务中保存 `closed_at`、实际操作账号 `closed_by` 及当时角色 `closed_by_role`。角色为 `user`（用户）或 `admin`（客服），从已鉴权身份和访问入口确定，不能由请求正文指定；管理员从个人工单入口操作仍记为用户。自动过期记录 `system`（系统），不关联人工账号。相同终态的重复操作返回首次记录，不覆盖原结单人或时间；已完成与已撤销之间不能相互改写。用户账号删除导致外键清空时，角色快照仍保留。

用户和管理员都能在列表及详情的终态徽标旁看到结单方。历史已完成或已撤销工单缺少可信的操作身份时，保持账号为空、角色为空字符串，并显示“未记录”；不能按最后一条回复推断结单人。历史过期工单可显示系统。

优先级只有低、中、高，协议值保持 `low`、`normal`、`high`，默认中。管理员列表按高、中、低优先级，再按更新时间倒序排列，支持类型、状态、优先级和标题搜索。创建时锁定用户并检查未关闭工单数；回复、关单和调整优先级在事务内锁定工单。创建和回复支持 `Idempotency-Key`，同键同内容重试复用结果，同键不同内容拒绝，避免网络重试重复创建消息。

新建工单标题去掉首尾空白后最多 50 个 Unicode 字符，前端显示字数，服务端同样检查；超限返回 `TICKET_TITLE_TOO_LONG`（400），不截断保存。已有历史标题保留原文，不收缩数据库列或回写历史数据。

用户和管理员列表均提供完成、撤销操作，并显示确认框；终态不再显示这些操作。列表使用布局提供的单一页面标题，列表及详情中的长工单标题省略显示，悬停提示保留完整内容。详情只显示一个工单主标题，信息和操作默认直接展示，没有信息折叠标题和重复正文标题。详情对话区独立滚动，回复区保持在视口内，附件选择区可折叠；刷新时保留历史消息阅读位置，发送回复后定位到最新消息，窄屏和矮屏使用紧凑布局。

核心入口：`backend/internal/service/ticket.go`、`backend/internal/repository/ticket_repo.go`、`backend/internal/handler/ticket_handler.go`；表由 `273_support_tickets.sql` 新增。后续 `274_support_ticket_consultation_type.sql` 将历史售前、售后及其他类型合并为咨询，保留工单标识、内容、消息、附件和幂等哈希，不修改已存在的迁移文件。服务层接受旧类型别名并规范化，数据库触发器同样兼容滚动升级期间旧程序的写入；旧类型请求仍按原始输入计算幂等哈希。

优先级调整使用 `275_support_ticket_three_priorities.sql`，将历史紧急（`urgent`）归入高，并兼容旧实例写入。旧优先级请求按原优先级保留创建幂等摘要，既有消息、附件与工单标识不变。旧 `assigned_to` 数据库列保留用于升级兼容，新代码不读取或写入处理人员。

## 附件与传输

附件支持 JPEG、PNG、GIF、WebP、PDF、Word DOC/DOCX。服务端同时检查扩展名和真实格式，清理路径、控制字符和文件名长度，拒绝脚本或可执行文件的双后缀。创建和每次回复分别检查附件数量与单文件大小；所有附件合计每请求最多 50 MiB，内容处理后的大小也须满足限制。

- 图片限制单边 16384 像素、总像素 4000 万，完整解码后重新编码，仅保留像素，清除元数据及尾随载荷。JPEG 以质量 95 编码；GIF 仅保留首帧；WebP 转为 PNG 并同步修改文件名与 MIME。每进程最多同时处理两张图片，不排队积压大文件。
- PDF 使用 `pdfcpu` 解析对象结构，兼容普通及压缩对象 PDF；拒绝加密文档、脚本、自动动作、嵌入文件及危险链接协议。限制文件 20 MiB、对象与交叉引用条目各 10000、递归 64 层、单流解压 8 MiB、累计解压 32 MiB，并设置 5 秒解析上下文及累计读取预算。每进程最多同时检查一个 PDF；检查过程不访问网络、不创建解析器配置目录、不渲染页面或执行文档内容。
- DOCX 检查 ZIP 全部条目的路径、重复项、压缩前后大小和文件类型，最多 1024 条目、累计解压 64 MiB；解析所有 XML 和关系文件，拒绝 DTD/实体、宏、ActiveX、嵌入对象、DDE/动态字段及外部模板或资源加载。普通 HTTP、HTTPS、mailto 超链接可保留。DOC 检查复合文档目录和完整流链，拒绝宏、嵌入存储、加密、模板及损坏或循环流链。

文件格式或危险内容检查失败返回 `TICKET_ATTACHMENT_INVALID`（400）。图片或 PDF 的处理槽位已满时返回 `TICKET_ATTACHMENT_BUSY`（503），前端保留选中文件以便稍后重试。以上是格式、主动内容和资源防护，不是病毒扫描，也不承诺识别所有恶意样本。

附件元数据和内容存放 PostgreSQL，与工单消息在同一事务中写入，因此备份数据库同时包含附件。列表、详情只返回元数据，文件内容仅从专用鉴权接口读取。用户只能查看或下载自己工单的附件，管理员可访问全部工单附件；管理员从个人入口访问时仍受本人归属限制。原件接口保持强制下载；新增同一路径下 `/preview` 返回 `inline` 内容。两者均禁止缓存和 MIME 嗅探、设置 CSP 沙箱、禁止嵌入和不发送来源信息，不提供公开静态目录，不按上传文件名落盘或执行附件。

创建与回复采用 multipart：`payload` 为 JSON，`files` 为重复文件字段。用户和管理员点击工单对话中的附件名称，在当前详情内打开站内预览弹窗，不跳转或新开标签页；关闭弹窗保留回复草稿及对话阅读位置。已有独立预览地址保留兼容入口，与弹窗共用预览组件。两种入口都遵守原详情的登录、管理员及工单开关约束，浏览器以认证请求获取 Blob，令牌不写入链接；不将私有附件传给外部 Office 或 PDF 查看服务。

预览前对历史文件重新执行当前格式和主动内容检查，使用单文件 20 MiB 硬上限；调低当前上传数量/大小或关闭附件上传不阻止已存附件预览，关闭整个工单模块仍拒绝访问。图片重新编码后以图片展示；PDF 保持原内容，由本地 PDF.js worker 渲染单页并提供翻页，解析器、字符映射、字体和无 WASM 图片解码器随前端构建发布，禁用 XFA，不执行文档脚本、生成文档中的 HTML 或自动打开外部链接。一次只绘制一页，画布边长最多 4096、总像素最多 800 万；关闭弹窗、退出、失败或切换预览时取消读取与渲染任务并释放对象 URL 和 worker；切换工单或确认模块关闭时同步关闭当前预览。

Word DOC/DOCX 返回 `text/plain; charset=utf-8` 正文，由 Vue 文本插值显示段落和表格分隔，不作为 HTML 渲染。DOCX 重新校验整个 ZIP/XML 后读取正文，DOC 在安全检查后有界读取 CFB 流与 Word 97+ piece table，支持 Unicode 与压缩字符文本；每进程最多同时提取两份 Word 文档，DOC 正文最多 2 Mi UTF-16 单元，提取结果最多 8 MiB。正文预览不还原图片、页眉页脚和复杂排版，页面保留下载原件；不支持或损坏的旧格式明确返回 `TICKET_ATTACHMENT_PREVIEW_UNAVAILABLE`，不输出乱码或静默改为下载。纯图片 Word 文档可能没有可提取正文，前端显示空正文提示。

## 配置与通知

系统设置的工单设置独立保存到 settings，键统一以 `ticket_` 开头。默认启用；每用户最多 3 个未关闭工单；每次最多 5 个附件；每附件 10 MiB；客服操作邮件通知默认关闭；等待用户回复 72 小时后过期。客服操作邮件通知沿用 `ticket_notify_on_staff_reply` 配置键，共同控制客服每次新回复、完成及撤销工单的通知，保留已保存的开关值。

可配置范围：未关闭数 1–100，附件数 0–10（0 禁止附件），单文件 1–20 MiB，过期时间 0–8760 小时（0 关闭自动过期）。配置读取故障会返回错误，不能绕过总开关、数量及大小限制。

系统设置 → 工单设置中的开关控制整个模块。关闭后隐藏用户和后台工单导航并阻止页面进入，所有用户及管理员工单业务接口（列表、详情、新建、回复、优先级、完成、撤销和附件下载）返回 `TICKET_DISABLED`（403）；上传在解析正文前检查开关。用户 `/config` 与管理员 `/settings` 读写不受开关限制，管理员可重新开启。关闭不删除历史记录，后台过期扫描暂停，尚未发送的回复通知被跳过；重新开启后恢复访问，过期仍按原最后客服回复时间计算。

公开设置和 HTML 注入均包含 `ticket_enabled`，缺失时默认开启以兼容旧版本。独立工单设置保存成功后触发已有 HTML 注入缓存失效回调，当前浏览器同步公开设置中的开关。请求期服务端直接读数据库配置，旧页面或其他实例的界面缓存不能绕过关闭状态。

客服每条新回复提交成功后按通知开关发送 `ticket.staff_reply` 邮件；同一工单的不同消息独立投递，去重身份使用 `support_ticket_message` 与本次消息编号。客服首次完成或撤销成功后分别发送 `ticket.completed`、`ticket.cancelled`，去重使用 `support_ticket`、工单编号及事件类型。关单事务仅在首次提交成功后设置内部 `ClosureCreated` 标记；终态重试、用户个人入口自助结单和自动过期不触发客服结单邮件。回复与关单事件进入同一有界队列，发送时重新检查模块和通知开关。

发送通过现有通知模板和 SMTP 配置，三个工单事件均支持中英文模板，共享原 `ticket.staff_reply` 邮箱退订偏好，避免新事件绕过已有退订。退订链接的 GET 只显示确认页，防止邮件客户端预取或安全扫描直接退订；只有用户明确 POST 才保存偏好。持有效工单邮件链接的已退订用户可以在该页主动恢复工单通知；恢复写入优先级更高的 v2 已订阅偏好，兼容历史退订键，不自动改变任何已有选择。

发送失败记录事件、工单及消息标识，不回滚已提交的业务操作。通知服务记录 SMTP 接受、重复投递跳过与退订抑制，收件人仅记录哈希；SMTP 接受不代表最终到达收件箱。通知使用有界内存队列，进程异常退出时尚未发送的通知不会自动重放；工单消息保留在数据库中。

用户接口位于 `/api/v1/tickets`，管理接口位于 `/api/v1/admin/tickets`，设置使用管理前缀下的 `/settings`。前端入口为用户工单、后台工单管理，以及系统设置内的工单设置标签。
